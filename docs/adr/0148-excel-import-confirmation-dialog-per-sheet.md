# Excel 导入：一律经确认对话框，逐 sheet 勾选导入

## Decision

每个 `.xlsx` 工作簿的导入一律先停在**确认对话框**，无论自动规整成败：规整成功的 sheet 带检测到的表头行作为预填猜测、**默认勾选**；规整失败的 sheet 带失败原因、**默认不勾**——算法没把握的形状必须经用户预览拍板。对话框为 master-detail 双栏：左栏逐 sheet 勾选（状态图标 + 行数 + 「已选 N / M」计数），右栏为激活 sheet 的分页预览 + 表头行指定 + 跳过行勾选。提交只导入勾选的 sheet，规整猜测仅作为用户可见的默认值——**可见不等于确认，勾选才是**。已提交的每个 sheet 以显式规整参数（User 溯源）记录；未勾选的 sheet 被服务端跳过，空勾选被服务端拒绝。已知限制：重放恢复腿（resume 异常路径）依旧拒绝 `.xlsx`——未勾选 sheet 无快照无 recipe 条目，快照命中恢复不受影响；恢复路径 = 重新导入。CSV / Parquet / JSON 路径不变。

## Context

原模型（ADR-0015）只在规整失败时弹引导：全绿工作簿零交互直接进工作集，用户从未见过导入了什么；任一 sheet 失败则整书停车，一个坏 sheet 拖累全部。两条痛点同源——**工作簿内没有逐 sheet 的去留决策点**。预览与批次管道（分页预览、表头预填、批次 park/resume、固定高度骨架）已在失败路径上建成，确认所需的全部管道就位。

## Why

1. **信任底线前移**：ADR-0015 的底线是「不让脏表进工作集」，但「全绿直接进」让算法对表头/结构的猜测未经任何用户目光就落库——猜测不是确认，自动化不该替用户拍板工作集的内容。
2. **失败不再连坐**：勾选即粒度，坏 sheet 不勾即可，其余 sheet 照常导入；不再是全有或全无。
3. **可见 = 确认闭环**（呼应 ADR-0042）：导入即所见——用户勾了什么、表头在哪、跳了什么，提交的正是用户看过并同意的。

## Considered options

- **保留全绿快路径、仅失败弹窗**（现状）：工作集内容无确认点，痛点不消。**否决**。
- **规整失败的 sheet 默认勾选**：用规整算法的回落值（表头第 1 行）当用户确认，拍板未经预览。**否决**。
- **全展开单列堆叠（无 master-detail）**：10+ sheet 时预览堆叠失控。**否决**。
- **ADR-0015 行内修订**：翻转埋进原文，「引导加载」语义在各段膨胀。**否决**——新 ADR + 0015 加被延伸标记。

## Consequences

- **延伸 ADR-0015**：本 ADR 把「失败才弹引导」翻转为「每个工作簿一律经确认对话框 + 逐 sheet 勾选」；引导加载成为 Excel 导入的必经交互，0015 Consequences 已追加指针。
- 每个工作簿导入多一次确认交互——信任成本是显式的，不再由算法代付。
- 引导提交语义翻转：无 guidance 条目的 sheet 跳过（不再是默认表头第 1 行导入）；空 guidance 是服务端兜底错误。
- Auto 溯源标记不再产出；保留该变体仅为旧持久化描述符可反序列化。
- 工作区共享面对 `.xlsx` 的拒绝不变——解禁后复用同一对话框（后续决策）。
- 换源（`replace_source`）对 `.xlsx` 的拒绝不变；本对话框是将来 Excel 换源的地基。
- resume 两腿均不复活未勾选 sheet：快照命中恢复零源重读，重放腿拒绝 `.xlsx`（恢复 = 重新导入）。
