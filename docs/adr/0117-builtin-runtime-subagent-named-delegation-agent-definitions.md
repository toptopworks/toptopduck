# 内置运行时子智能体委派：具名委派工具族与 agent 定义

## Decision

1. **委派形态 = 注册表即委派面。** 内置运行时的轮次工具面新增**具名委派工具族**：agent 定义注册表中每个启用的条目对应一个具名委派工具（工具名 = 定义名，kebab-case、≤64、唯一、不撞保留工具名，校验沿用 CLI 注册项先例），主 agent 像调用普通工具一样把任务委派给该定义装配出的子智能体；不设单一通用委派元工具。子智能体 = 主 agent 轮内派生的嵌套执行体：独立上下文窗口、可并行、终局汇报回主轮、落幕即弃。

2. **agent 定义 = 社区格式单文件与机器级注册表。** 每个定义是一个 markdown 文件（注册表目录下、文件名 = 定义名）：frontmatter 承载 `name` / `description`，正文即 preamble（子智能体的 system prompt）；文件名与 frontmatter name 的一致性校验沿用技能 loader 先例。格式对齐社区 subagent 文件形态（事实分发标准）——导入即拷文件、导出即社区文件，零转换、零私有 schema 扩展字段；社区格式的 `tools` / `model` 轴本 ADR 已否决，导入时宽容降级（解析后丢弃、设置面警示，不硬拒不静默）。description 是外层主 agent 的委派路由依据（内嵌进工具描述）。技能专长 = preamble 正文中反引号包裹的技能名标记：装配时以技能注册名单与正文做交集提取，命中的技能正文构造时一次性注入子上下文（不走 `activate_skill` 通道、不写会话激活集、落幕即弃）——绑定规则一句话可文档化（反引号包裹的技能名即绑定），漏标记退化为纯提及无破坏；反引号引用不在名单时装配期跳过并警示、不炸轮。工具白名单轴与模型轴不开：前者是纯收窄轴（子面政策已是收窄，权限安全由审批同构覆盖）；后者维持「活跃接入档案至多一个」不变量，子智能体复用同活跃档案同思考姿势。注册表为机器级**单文件注册表**（目录扫描 = 注册表、无 sidecar 表，资产形态与技能同轴——定义是可分发资产，未来导入/插件/云端多源接入退化为文件系统动作、零迁移），`source` 由文件系统性质派生（真文件 = 用户、symlink = 链接、代码内置定义物化 + 标记 = 内置），`enabled` 为机器级单轴、住 app-config 名字集合（状态而非实体）——启用即直列进每轮工具面、禁用即隐身，无会话级挂载生命周期（定义体量小、常驻成本低；会话级语义空间刻意空置）。

3. **内置兜底角色 `general-purpose`。** source: builtin、preamble 正文不含技能绑定、不可删除——零自定义条目时主轮仍有委派能力。

4. **子面同构与深度排除。** 子智能体工具面 = 全量网关面**减全部委派工具减 `activate_skill`**（深度 1 物理排除——子构造时不挂任何委派工具，不可递归；会话级突变仅用户与主 agent 可为，`read_skill_file` 与发现面三件套保留）。审批、审计、物化命名与主 agent 完全同路径：子智能体的 explore/materialize 经同一 dispatch 核心直接作用主工作集，物化即晋升 `result_N` 同轨，scratch 子末即弃；审批弹窗标明发起方。

5. **分层预算与诚实回传。** 主轮步帽内一次委派计 1 步；子智能体内部步帽（10）独立计数；墙钟不分层——主轮无进展看门狗覆盖整轮含全部子智能体时间。同批并行委派上限 8，超出返回明确错误；帽批宽不帽总量（串行多批受步帽与墙钟自然约束）；数字进本 ADR、不进用户配置轴。子失败（步帽耗尽 / provider 错 / 循环检测停）= 委派工具返回诚实失败文本入主轮轨迹，不升级整轮 failed；死前已晋升的 `result_N` 保留；取消令牌自动转发、整轮照常 cancelled。

6. **嵌套子轨迹沿用瘦身投影。** 委派在主轮轨迹是一条工具调用条目，其下挂嵌套子轨迹（子 thinking + 工具串 + 终局汇报）；持久化沿用与主轮相同的瘦身投影（成功摘录清空、失败摘录截断、参数短摘要），远窗只收摘要；查看呈现形态留实施期。`.duck` 为纯文本 recipe、不含数据表（物化表住内存引擎），轨迹是其主要构成之一——子轨迹不得引入完整工具结果落盘通道。

7. **术语与校准面。** 新增词条「子智能体」（轮内嵌套执行体，由 agent 定义装配；非轮次、不推进计步序、不构成新运行时段）与「agent 定义」（注册表实体，中性命名——实体名不绑定单一消费用途，未来第二消费面（如会话级助手预设）与本职责不冲突时另行评估共用或分立）；「执行轨迹」「运行时」「网关」三处校准。

校准：v1 仅内置运行时装配委派工具族——外部运行时桥接面无此族（能力差异先例 ADR-0095，跟随留尾）；并行审批的排队呈现为留尾，形态不在本 ADR 定。

## Context

内置运行时自 ADR-0116 起以 rig（rig-core + rig-agent）为循环内核，轮次装配即 `AgentBuilder` + 网关工具的动态适配器直列。rig 原生提供子智能体机制的全部构件：`Agent::into_tool()` 把任意配置好的 Agent 转为 `DynamicTool`（工具名 = `name`，描述内嵌 description 与 preamble，参数为单一自然语言 prompt）；`AgentBuilder` 提供 name/description/preamble/工具集/步帽字段；`ToolContext` 自外层向子自动传播（取消令牌与会话身份继承）；`AgentHook` 提供模型响应、工具调用/结果、流式 delta 的观测点且嵌套栈语义明确。子智能体的挂载与既有网关工具装配完全同构——多构造几个动态工具即可，无新接缝。

数据分析轮次存在委派的真实动因：探索性长链污染主窗口（子智能体的独立上下文是隔离手段）、串行探索吃满墙钟（同批并行是延迟收益）、探索性失败是正常分支（工具级诚实回传让主 agent 可补救）。「角色分化」随自定义需求从成本变为价值——仅 preamble 的自定义只是换个人设，所有子智能体能力面相同；技能装配期绑定让定义同时携带人设与专长两个维度。无角色的单一通用委派形态以单一机制上游（被替换的循环 crate 仅提供单一通用子智能体工具）为前提，该前提随 ADR-0116 失效——rig 下具名形态是第一映射，无角色反而要 app 层额外合成削平。

## Why

1. **上下文隔离与并行是轮次执行的真实瓶颈**：探索性长链污染主窗口、串行探索吃满墙钟，委派同时解两者且失败可补救。
2. **上游原生形状使角色库边际成本趋零**：具名 agent 即工具是 rig 的第一映射，削平为单工具反而要 app 层合成——形态选择跟随依赖的真实形状。
3. **自定义的价值主张 = 人设 + 专长**：技能装配期绑定注入让定义同时携带两维度，且不触碰激活不变量（激活通道仍仅用户与主 agent 可为）。
4. **同构不变量兑现零新通道**：子智能体经网关装配面，审批/审计/物化/编号 identical by construction，无第二执行路径。
5. **持久化零膨胀**：瘦身投影 + 步帽上界使子轨迹增量最坏为百 KB 级文本，对纯文本 recipe 无压力。
6. **可分发资产走文件形态**：agent 定义是导入 / 插件 / 云端多源资产，文件即资产、与技能同轴，社区格式对齐使导入导出零转换；机器级状态（`enabled`）与实体分离、各归其轴。

## Considered options

- **单一通用委派工具、无角色分化**：仅 preamble 的自定义不构成价值主张；其「上游仅单一机制」前提随 ADR-0116 失效。**否决**——具名委派工具族（Decision 1）。
- **运行中开放 `activate_skill` 给子智能体**：子智能体一次性装配，运行中激活的正文进不了自身上下文（对己零收益）、却突变会话级持久状态（无对价突变）；且子面无激活通道下，装配期注入是技能正文进入子上下文的唯一通路。**否决**——装配期技能绑定（Decision 2）。
- **实体住 app-config 注册表节（CLI 注册项同款惯例）**：agent 定义是可分发资产（未来导入 / 插件 / 云端多源），app-config 是应用配置状态单文件——资产入配置混淆两类持久化，且多源接入（拷贝 / 链接 / 放置）在单文件节上均退化为表级合并、未来必然迁出。**否决**——单文件注册表、与技能资产同轴（Decision 2）。
- **skills 为 frontmatter 结构化字段**：私有 schema 破坏与社区格式的零转换对齐，而绑定来源用正文反引号标记即可承载（标记即正文书写，规则一句话可文档化）。**否决**——正文标记 + 名单交集提取（Decision 2）。
- **隔离工作集副本 + 终局回传**：第二物化路径，审批/编号/晋升语义分叉，违背网关同构。**否决**——共享主工作集（Decision 4）。
- **子面只读（移除 materialize）**：探索成果退化为文字转述，委派价值大打折扣。**否决**。
- **agent 定义开工具白名单轴**：纯收窄轴且权限面已由审批同构覆盖。**否决**——需求出现时加轴不动架构。
- **agent 定义开模型轴**：动摇「活跃接入档案至多一个」不变量。**否决**。
- **会话级挂载生命周期（技能式 mount）**：定义体量小、常驻成本低；会话级语义空间留给未来消费面。**否决**——机器级单轴（Decision 2）。
- **会话级助手预设并入本链**：另一消费面、机制正交，需求与切片另行评估。**否决**——本链不含。
- **子轨迹完整落盘**：`.duck` 为纯文本 recipe、轨迹是其主要构成，完整工具结果落盘无上界。**否决**——瘦身投影（Decision 6）。
- **外部运行时同步装配委派面**：外部 CLI 的工具面由其自身进程构造，app 无委派构造点。**否决**——内置先行、外部留尾。
- **有限深度 >1（计数制）**：步帽按层重置乘法爆炸、任务简报可诱导自委派螺旋。**否决**——深度 1 物理排除（Decision 4）。

## Consequences

- **CONTEXT.md**：三处修订（「执行轨迹」「运行时」「网关」）+ 两新增词条（「子智能体」「agent 定义」，见 Decision 7）。
- **轮次工具面随注册表条目数增长**：token 成本为用户策展责任，与 CLI 注册项同轴。
- **委派调用入主轮计步序**（1 调用 = 1 步），主 agent 的预算感知与帽值语义不变（ADR-0081）。
- **留实施期**：子轨迹查看 UI 形态；rig 同批工具调用的并发执行语义核实（「允许并行」决策不受影响）；审批发起方标注的 ToolContext 载荷形状；`general-purpose` 的 preamble 文案；agent 定义 frontmatter 解析器与社区格式宽容降级的实现面。
- **留尾**：外部运行时委派跟随；并行审批排队呈现；会话级预设第二消费面。
- **边界不变**：「激活仅用户与主 agent 可为」；`activate_skill` / `read_skill_file` 的条件挂载语义（ADR-0110/0111）。
