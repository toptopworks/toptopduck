# 轮次看门狗：无进展语义取代整轮墙钟

## Context

ADR-0081 执行级兜底 = 步数上限（24）+ 墙钟 watchdog（120s，对齐 ADR-0021 `REQUEST_TIMEOUT`），触顶该轮 failed/cancelled，cancel = 整轮中止。watchdog 从轮次起点一次性计时、不随任何活动重置；其立法理由（ADR-0081 Why 5）是「agent 可能不收敛，步数 + 墙钟是最后防线」。

ADR-0080/0083 定审批为流内审批卡片：外部运行时的调用命中确认时在网关挂起等待用户，无时间上界——审批打断是 app 的 UI 打断点。

两个决策从未对齐：整轮墙钟把两类「非 agent 不收敛」的耗时计入同一上限——**审批挂起**（人在决策，人因延迟）与 **CLI 工具执行**（合法慢；CLI 工具无独立超时，耗尽整轮墙钟）。外部运行时的代码解释器调用在工具执行段即触顶——观测中连续轮次均于约 2 分钟整中止。ADR-0081 未决（实施期）「ACP `session/request_permission` 与网关审批对应」落地后，权限挂起同样计入整轮墙钟，冲突由此成立。

## Decision

墙钟 watchdog 重定义为**无进展看门狗**：

- **计时面**：仅对 agent 自由活动段（生成段）计时；判据 = 生成段持续无流活动达 120s（帽值与 ADR-0021 对齐保留）。
- **冻结面**：轮次等待外部主体的段一律不计时——网关工具执行（CLI 工具无独立超时的现状不变）、审批挂起（ADR-0080/0083 的 pending 卡）、外部适配器自身工具执行（执行轨迹的调用开区间）。
- **双路径共享同一谓词**：内置 yoagent 循环在工具 dispatch 与审批挂起段不计时；外部适配器引擎在 tool_call 开区间与 `request_permission` 开区间不计时；任何入站流活动重排计时器。判据不收窄为「可解析帧活性」：解析失败的入站行同样证明子进程存活与产出，收窄会把「引擎读不懂」误判为「agent 无进展」；噪声流的可观测性由泵顶层丢弃点的计数 / 限频日志承担。
- **落点不变**：cancel = 整轮中止（ADR-0021/0081 保留）；outcome 落 cancelled；失败细节通道携带「无进展超时」技术细节（错误分层面），UI 措辞区分留实施期。
- **步数上限 24 不变**；记复议触发器：出现超出 24 轮（执行轨迹分组轮）的合法收敛轨迹即复议提额。
- 每适配器帽值覆盖缝保留为测试缝，不产品化。

## Why

1. **立法目的归位**——ADR-0081 自己把墙钟定义为防不收敛的安全网；人因延迟与合法慢不属于「不收敛」，计入即范畴错误。
2. **审批等待不计时**——用户读审批卡期间轮次被中止，会把用户推向免确认模式，反向侵蚀 ADR-0080 分级审批的使用率。
3. **判定力增强**——旧语义要求整轮在 120s 内完成，新语义只要求生成段每 120s 内有流活动；合法长工作流（文档生成类多步工具链）在每次工具调用处重排计时器，永不触顶。
4. **机制最朴素**——冻结是在已知相位不启动计时器，无需跨进程活性信号；真僵死由既有 stop（cancel + SIGTERM fallback）与会话关闭清算兜底。

## Considered options

- **维持整轮墙钟（现状）**：审批等待与长工具执行被系统性误中止，重试同命运。**否决**。
- **资源占用上限语义（人因延迟计入上限）**：与 ADR-0081 立法语言相悖，UX 反直觉。**否决**。
- **帽值提升（300s 等）**：不修语义只放大上限，合法场景仍被中止，且放大失控轮次最坏时长。**否决**。
- **活性轮询（子进程存活 / CPU 活动即进展）**：判定力最强但需跨进程活性信号，机制最重。**否决**——YAGNI。
- **帽值产品化可配**：现有适配器均流式，「整段生成单更新送达」的静默场景不存在。**否决**——YAGNI，缝保留。
- **步数上限顺带提额**：无现场数据，且墙钟放松后双重削弱安全网。**否决**——记复议触发器。

## Consequences

- **校准 ADR-0081**：执行级兜底的墙钟条款由本 ADR 取代；步数上限、cancel = 整轮中止、ADR-0021 `REQUEST_TIMEOUT` 对齐保留。
- **延伸 ADR-0021**：120s 的对齐语义保留，对齐对象由「整轮时长」改为「生成段无进展时长」。
- **闭合 ADR-0081 未决项的墙钟相斥面**：`session/request_permission` 与网关审批对应落地后，审批挂起是冻结相位、无超时上界；pending 审批卡不会因看门狗触顶转 deny。
- **CLI 工具执行维持无独立超时**：其时长风险由冻结语义吸收；真僵死由用户 stop 或会话关闭清算处置。
- 中止落点复用 cancelled；「已取消 / 已超时」的 UI 区分是实施期 follow-up。
- CONTEXT.md 增术语「无进展看门狗」。
