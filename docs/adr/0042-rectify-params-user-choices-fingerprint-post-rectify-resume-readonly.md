# Rectify params in recipe: user choices only (not result snapshot); content fingerprint = v2 source-hash equivalence; resume read-only, fix via re-upload

## Decision

1. **规整参数 = 用户的显式规整决策**（表头行号、跳过行范围、sheet 选择、列类型覆盖——ADR-0015 引导加载 / ADR-0020 类型暴露时用户拍板者）。**自动规整算法**（表头探测、解合并单元格、公式取缓存值）**不进参数**——它是代码，resume 重跑当前版本。

2. **内容指纹 = v2 源哈希等价**（取代整表导出哈希）——`v2:` 版本前缀 + copy-in 实际读取文件的流式 SHA256 + 生效 reader fn 拼写。等价论证：`read_*` 构建确定性 ⇒ 源字节唯一决定表内容；reader 拼写只记 fn 名（UTF-16 定重试腿是源字节的纯函数，fn 名下等价论证仍成立）；derived 引用的 SQL 参数已参与 chain_digest，rebuild 触发即参数未变。Excel 每 sheet 哈希各自物化的临时 CSV（copy-in 的真实输入），规整选择经物化内容参与指纹。

3. **resume 重建 + 校验**：读源文件 → 应用规整参数 + 当前算法 → 产出快照 → 校验 v2 指纹 == recipe 记录。符则静默进入；不符走 ADR-0035 漂移降级。**指纹算法升级**（无前缀旧指纹遇 `v2:` 新指纹）≠ 数据漂移——比对时放行 + log，recipe 保持原值不回写（回写会改 chain_digest，下次 watermark 必 miss 逼全量重放；自然收敛 = 源真被替换或重传时写入 v2）；后续解析腿变化（如新增 pinned 重试）再升 `v3:` 前缀。算法漂移的自然命中面收窄为 reader 拼写变化。

4. **换源 = 对新源重新规整**：走 ADR-0015/0020 流程，产新规整参数 + 新快照 hash；旧规整参数随旧快照丢弃。规整参数是源引用的一部分（ADR-0034），换源 = 替换整个源引用（路径 + 规整参数 + 指纹）。

5. **resume 后规整参数可见只读**；修正规整的唯一路径 = **重新上传 = 换源**（ADR-0025）。换源判定依据精确化 = **指纹变了**（v2 源哈希不同），非「文件变了」——**同源文件 + 不同规整也算换源**（规整改变 copy-in 实读的物化内容 → 新指纹接管旧引用名 + 级联失效派生）。

6. **CSV/JSON v1 无用户规整参数**（ADR-0020：纯 DuckDB 自动类型推断、不做引导式类型确认）；其规整参数基本空，copy-in 的确定性纯靠 v2 源哈希校验。

## Context

ADR-0034 的 recipe 结构「源引用 = 路径 + 规整参数 + 内容指纹」里，**「规整参数」是黑盒**（0015 的交互产物如何序列化未定）、**「内容指纹」语义未钉**（源文件原始 hash 还是规整后快照 hash）。规整是「源文件 → copy-in 快照」的转换，而 0034 承诺 recipe 是工作集的「完整无损」描述、resume 重建出**完全相同**的快照（ADR-0012）——这个转换的**确定性保证从哪来**未定。是 0015 自陈「导出路径策略另定」已被 ADR-0038 收口、但其规整交互产物如何进 recipe 仍未闭合的依赖。

## Why

1. **KISS + 兑现 0034 完整无损**：规整参数轻量（只记用户决策），配 v2 源哈希校验（copy-in 一次流式，免整表导出），确定性保证由「read_* 确定性 + 等价论证」兜底，而非靠记全量规整结果。
2. **漂移统一捕获**：源文件改 / reader 拼写变，都表现为「重放指纹 ≠ 记录指纹」，同一 0035 降级路径；指纹算法升级经版本前缀区分，不与漂移混淆。
3. **可见只读避免级联陷阱**：会话内改规整会触发 ADR-0025 级联失效，用户难理解「为何改个加载设置炸了整条分析链」；修正统一走重新上传（0012/0020 既有路径），KISS/DRY。
4. **边界假设显式化**：本模型依赖「自动规整算法是确定性的（给定输入 + 版本 → 确定输出）」。若将来规整引入不确定性（如 ML 启发式），须把结果也记进参数——届时另开 ADR 校准本决策。

## Considered options

- **规整参数记完整结果快照（版本无关）**：自包含但 recipe 膨胀；且快照 hash 校验已能捕获算法漂移、诚实降级，无需全量记结果。**否决**。
- **内容指纹 = 规整后整表导出哈希（post-load dump）**：GB 级源上整表导出 + 临时落盘 + 读回是导入链路的最大单项开销，临时文件额外占用与表内容等量的磁盘；源哈希等价论证成立后为纯浪费。**否决**。
- **内容指纹 = 裸源文件 bytes hash（无 reader 拼写、无版本前缀）**：同一字节经不同 reader 产出不同表；且算法升级与源漂移无从区分。**否决**。
- **resume 可见可编辑（会话内改规整）**：触发 0025 级联失效的隐式陷阱；且是「既触发级联又不算换源」的半新操作，语义模糊。**否决**。
- **换源继承旧规整参数**：新源结构不同（表头行变了），旧参数大概率无效。**否决**。
- **算法升级时静默用新算法重算老文件**：静默产出微妙不同的快照，违 ADR-0011/0017/0030 诚实脊柱。**否决**。

## Consequences

- **精确化 ADR-0034**：recipe 源引用的「规整参数」「内容指纹」语义钉死——规整参数 = 用户规整决策（非结果快照）、内容指纹 = v2 源哈希等价。0034 Consequences 已追加指针。
- **精确化 ADR-0035**：内容指纹 = v2 源哈希；源漂移走本 ADR 漂移降级，指纹算法升级经版本前缀放行。0035 Consequences 已追加指针。
- **精确化 ADR-0025**：换源判定依据 = 快照变（含同源文件不同规整），非文件变。0025 Consequences 已追加指针。
- **延伸 ADR-0015**：引导加载（表头行/跳过行）的用户交互产物 = 进 recipe 的规整参数；resume 后可见只读，修正 = 重新上传（= 换源）。0015 Consequences 已追加指针。
- **延伸 ADR-0020**：CSV/JSON v1 无用户规整参数（纯自动类型推断）；其快照确定性靠 v2 源哈希校验。0020 Consequences 已追加指针。
- **延伸 ADR-0012**：copy-in 快照的 resume 重建路径钉死 = 读源 → 应用规整参数 + 当前算法 → 产出快照 → 校验 v2 源哈希（不符走 0035 降级；无前缀旧指纹按算法升级放行）。0012 Consequences 已追加指针。
- **不改 CONTEXT**：规整参数是 recipe 的结构字段（实现细节），非用户面领域术语；用户面概念「规整」已在 CONTEXT「数据集」条目 + ADR-0015 覆盖。CONTEXT 须 devoid of implementation details。
- 实现侧：规整参数序列化（格式相关——Excel 有、CSV/JSON 空）、v2 源哈希（copy-in 时一次流式）、resume 重放 + 校验（无前缀旧指纹按算法升级放行且不回写）、规整参数只读视图、换源对新源重新规整。
- **边界假设**：自动规整算法须确定性；若 v2 引入不确定性（ML 启发式），须把结果记进参数，另开 ADR 校准本决策。
