# recipe v2:晋升链 + 轨迹展示部分,单向迁移

## Decision

recipe 格式 bump `format_version`（v2）：**可重建部分**从 productive SQL 链变为**物化晋升链**（晋升条目 = SQL + 依赖引用 + `result_N`），resume 重放语义不变（源集载入 + 晋升链重放，ADR-0035）；**展示部分**轮次条目增加**轨迹子结构**（可折叠，ADR-0078）与轮次运行时 / 技能出处。**单向迁移**：首次打开自动 bump + 应用映射（存量 productive SQL 一对一映射为晋升条目；旧轮次的轨迹为单调用合成），旧客户端读新文件走现有 `VersionMismatch`「请升级」路径（ADR-0036）。

## Context

ADR-0034/0036 定 recipe-only 持久化 + `format_version` + 前向迁移链。ADR-0077/0078 使可重建部分语义（productive SQL → 晋升条目）与展示部分形状（轨迹）变更。旧→新映射无损：每条 productive SQL 恰是一个晋升条目。

## Why

1. **单向迁移复用 ADR-0036 机制**：迁移链注册、VersionMismatch UX、honest-degrade 现成，边际成本仅一个迁移步骤。
2. **双向兼容会迫使轨迹进旧客户端不可见的并行节**，语义双写双读；降级窗口的价值不抵双轨负担。
3. **并行新扩展名破坏 ADR-0034 可移植承诺**（单文件即会话身份）。
4. **映射无损且平凡**：productive SQL 与晋升条目的语义距离仅「哪轮产出」→「哪条轨迹调用晋升」。

## Considered options

- **双向兼容期（轨迹并行节、旧端不可见）**：双写 + 双语义。**否决**。
- **并行新格式（新扩展名）**：生态断裂、可移植承诺破。**否决**。
- **不迁移（新会话新格式、旧会话只读冻结）**：旧会话不能产出新轮次，用户数据实质作废。**否决**。

## Consequences

- **校准 ADR-0034**：recipe 可重建部分描述为晋升链；可移植 / derive-only / 机密边界不变。
- **校准 ADR-0036**：v2 迁移步骤注册进前向链；「旧客户端 honest-degrade」方向不变（单向）。
- **延伸 ADR-0035**：resume 完整性（指纹 / 单写者）不变；重放单位从 productive SQL 变为晋升条目。
- **延伸 ADR-0042**：rectify 参数骑源集条目，不受影响。
