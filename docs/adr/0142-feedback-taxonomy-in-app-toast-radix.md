# 反馈面：四层分类学与应用内 toast 定形（radix 配方、主区列顶居中）

## Decision

1. **反馈面定格四层分类学**：面板内错误横幅承载面板在场失败面——失败落定时归属面板还在场，在就地上下文里报错（ADR-0058 分层回退的面之一，层级不动）；toast 承载应用内瞬时事件反馈面——事件落定时归属面板已离场，或事件本身无面板归属；通知中心是持久收纳域；系统通知是 OS 层域。前两层属应用内 UI，随本决策定形；后两层是未来独立域，不随本决策建立。横幅与 toast 的分流判据是事件落定时其归属面板是否在场。分类学只装需要到达用户的失败与事件：无需用户感知的内部失败（仅日志）不进任何层，就地反馈（复制回执等组件内状态）保持就地，披露横幅（ADR-0033 模式的信息揭示面）是信息披露不是失败反馈，均不在分类学内。

2. **基建进 radix 家族**：`@radix-ui/react-toast` 与 shadcn 配方三件套（toast 组件、`use-toast` hook、Toaster viewport）进自有组件集。存量复杂交互组件以 radix 家族为主（dialog、dropdown-menu、select、tooltip 等），toast 进同族。

3. **落位与挂载**：Toaster viewport 挂 shell 根、跟随主区列——主区列水平中心、悬于会话内容顶部，滑动移除方向随落位（向上挥出）；主区列常在（冷启动同成立），落位不随面板挂载，面板开合与折叠时方位随主区几何重算（折叠动画过程中的亚秒级漂移豁免）。

4. **variant 与参数起步面**：`default` 与 `destructive` 两 variant 起步，不预做 success/warning；自动消失时长、堆叠上限走库默认，不调参。

5. **wording-free**：组件面零文案、零 i18n keys（ADR-0052 双语体系无增量）；`title`、`description`、`variant` 全由消费方传入，措辞与翻译归消费面。

## Context

应用零 toast 基建：依赖层无 toast 类包，shadcn 组件清单无 toast，反馈面现状是面板内错误横幅（ADR-0058）与就地确认。缺口在面板离场期间落定的失败——横幅随面板存亡，面板不在场即无处渲染，上传批次一类的数据操作失败就此静默，用户无从感知损失。应用内瞬时事件反馈面需要一个独立于面板生命周期的承载面。

## Why

1. **离场失败的可达性**：数据操作的失败在面板离场后静默，损失不可感知，与诚实报错的既有方向（ADR-0035）相悖；toast 独立于面板生命周期，失败落定时无论面板在场均可达。
2. **分层不互吞**：在场失败留在面板内错误横幅（就地上下文，ADR-0058 层级不动），toast 只收离场失败与瞬时事件；分流判据机械可判，无归属决策点。
3. **家族一致性**：toast 进 radix 同族，交互组件一套心智，portal 层、焦点管理、受控语义与存量组件同源。
4. **对话列注视区**：主体是对话流，主区列是产品本体，管理面板只是局部场景；瞬时事件反馈落在注视区内——失败面的被看见是诚实报错的硬需求，窗角是余光区。
5. **文案归消费方**：组件面无法预知消费场景的措辞，零预设文案使基建不绑任何事件词汇，翻译随消费场景进 ADR-0052 体系。

## Considered options

- **sonner**：上游 shadcn 配方当前默认；独立体系，与存量 radix 交互组件双轨，风格与行为对齐另起一摊。**否决**——radix 家族一致。
- **横幅唯一失败面（离场失败静默）**：数据操作失败不可感知，损失无声。**否决**——toast 承接离场失败。
- **通知中心/系统通知承接离场失败**：为单一失败面引入持久收纳或 OS 域基础设施，过重。**否决**——后两层独立建立。
- **success/warning variant 预做**：色彩语义先于消费场景定形。**否决**——两 variant 起步。
- **时长与堆叠调参**：参数先于真机使用依据。**否决**——库默认。
- **复制等就地确认迁 toast**：就地反馈在操作点上下文内，迁出即丢就近性。**否决**——就地姿态不动。
- **toast 挂面板树**：面板关即 viewport 消失，离场失败无处渲染，恰是要解的缺口。**否决**——shell 根挂载。
- **右下窗角固定**：桌面工具常规范式、零测量机制，但余光区在对话流主体下易被忽略，失败面可见性打折。**否决**——主区列顶居中。
- **主区列底（composer 上方）**：贴近流式输出的注视焦点，但遮挡主输入面，瞬时反馈打断主交互。**否决**——列顶悬停。

## Consequences

- 消费开口为 `toast({ title, description, variant })`；离场失败的具体分流与归因措辞归各消费面决策，本决策只定承载面与分类学。
- 成功事件不产 toast，成功回执仍走面板内状态；destructive 是离场失败的归因 variant。
- 控制件无障碍标签（关闭按钮的 sr-only 文案）随配方与 dialog 先例起步为英文，不视作组件面事件文案；与 ADR-0052 双语体系的对齐（连同 radix 库默认 a11y 文案）随首个消费场景定形。
- 通知中心与系统通知出现需求时独立定形，后台任务完成通知与 OS 通知域的联动不在本决策。
- 真机使用后复盘时长与堆叠默认，有据再调。
- 非目标：面板内错误横幅与披露横幅的既有面（ADR-0058/0033 不动）、就地反馈姿态、通知中心、系统通知。
