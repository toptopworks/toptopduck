# 内置运行时姿势：端点身份归属 + 档案模型可选化 + 起步回填

## Decision

1. **接入档案的模型是可选的钉选模型**。`profile.model` 可空：空 = 未钉选模型，是合法的持久状态——存储、规范化与 IPC 视图都以空态呈现，规范化只把空白值归为空，绝不回填成某个默认 id；后端不再持有默认模型常量，任何读取路径都不以默认 id 代替空值。预设的默认模型与新建档案的骨架预填是交互层便利，照旧保留。
2. **空模型档案的轮次诚实拒绝**。有 key、未钉选模型、且会话没有可注入的模型选择时，轮次在构造上游客户端之前拒绝，落专用的永久失败类别（未选择模型），零出网，文案引导去 composer 的模型菜单选择。优先级不变：无 key 无模型仍报未接线（配置 key 的信号在前）。绝不代猜模型——不取端点列表的首个，不取任何全局默认 id。
3. **提取通道同样诚实失败**。提取目标档案（提取模型指针，缺省回落活跃档案）的模型为空时，提取在构造前失败、零出网，面板以专属的失败面呈现并引导去设置页钉选模型；不回落到别的档案或默认 id。
4. **内置回填进同一张表、按端点身份分记**。内置运行时的「上次模型姿势」条目与外部通道同住 `last_model_postures`，键为活跃档案的端点身份（协议 + `base_url`，带保留前缀，与适配器 id 的命名空间不相交），由后端单点派生：新会话起步与会话内换到内置运行时都注入该端点的上次选择；同端点换档案共享条目；条目悬空（档案删除、端点改掉）保留不清，端点改回自动复效。每次成功的内置姿势 set 更新该条目（单一写入点）。读取走无参 IPC 命令——后端自查活跃档案派生键，前端零键知识。
5. **内置模型维没有「默认（推荐）」清除行**。内置运行时没有 CLI，「未选择」没有可依托的 CLI 默认行为，清除只会让下一轮拒绝；菜单 = 端点列表 + 钉选模型行（钉选模型不在列表时出合成行，可选中，即回到钉选模型的手势）。代价已接受：内置回填条目不可经菜单清成空态——选过之后，该端点的所有新会话起步于上次选择，要回钉选模型就选中它。强度维的清除行内外都保留（「不注入强度」是真实语义）；外部通道模型维的清除行不动（CLI 默认是真的）。
6. **内置姿势对携带端点身份（后端盖章）**。会话姿势槽与 recipe 头各带一个可选的端点身份字段，语义 = 选择时所属的端点；由后端在三个落点盖章（set 命令、起步注入、运行时切换，均读活跃档案现算），前端永不传（set 的 wire 仍是纯姿势对）。注入与显示用同一谓词：身份与当前端点一致才注入整对，不一致则整对按未选择处理——模型与强度一起落空，不存在「无模型的强度」；持久值不销毁，端点改回自动复效。composer 挂载期间观察到的端点变更仍走既有的运行时切换式重置（新时段按新端点回填，ADR-0153）；本谓词覆盖其余一切窗口。未盖章的对（存量 recipe，或外部通道的对落到降级的内置起步上）不匹配任何端点。存量 recipe 缺字段按空读取，不 bump format_version。
7. **按钮三态**。内置运行时的姿势按钮：已选择显「{model} · {strength}」；未选择且档案已钉选模型时显该模型的 id；未选择且未钉选模型显诚实的「未选择模型」态（中性色）。持久默认语义单源：姿势回填是内置运行时持久默认的唯一承载，`profile.model` 只是显式的初始默认；resume 恢复会话自身的姿势（连同其端点身份），不读回填表。

## Context

ADR-0153 给内置运行时接上了会话级的模型 / 强度选择，但把跨会话的持久化、`profile.model` 的必填语义、以及未挂载 composer 时的端点归属留给了后续。现状因此是：默认模型常量在后端兜底，规范化把空值回填成默认 id——而网关接入下钉哪个 id 都武断，网关伺服一串模型，钉死的回落值可能指向它并不伺服的 id；内置冷启动恒为空姿势（起步解析对内置分支返回默认值），每个新会话都要重选；姿势对不携带归属，端点在 app-config 里移动（切换档案、修改端点）时会话零写入，未挂载 composer 的会话与 resume 的会话会把外域模型 id 注入新端点。

## Why

1. **空是诚实态而不是缺陷**：网关的模型列表在配置时未知，强制用户填一个 id 只能靠猜；可选化后「未选择」有明确的出路（菜单里选），拒绝文案也指向它。
2. **回填与默认运行时同构**：内置运行时的高频微调（换模型、换强度）与外部通道同质，起步免于重复设置；按端点分记是因为模型 id 是端点事实——同端点的档案共享同一列表，跨端点互不相通。
3. **注入点自带身份才覆盖全部窗口**：前端的漂移重置只覆盖挂载期间观察到的端点变更；端点身份随姿势对持久化、并在注入与显示两处比对，未挂载与 resume 窗口同样成立，且不销毁用户已持久的选择。
4. **单一派生点**：端点身份的派生只在后端一处（回填键、盖章值、轮次比对共用），前端零键知识——第二处派生就是第二个人对「同一端点」的意见。
5. **提取通道不兜底**：提取是无人值守的后台调用，代猜模型会让失败静默发生在一个用户看不见的通道里；诚实失败加引导是唯一能被发现的形态。

## Considered options

- **保留后端默认模型常量、空值回填默认**：网关接入下默认 id 可能不被伺服，轮次以端点报错收场，用户无从得知是哪一层填的。**否决**——可选化加诚实拒绝。
- **拒绝时回落到端点列表首个或全局默认 id**：代猜武断，且把「用户没选」伪装成「用户选了」。**否决**。
- **用 InvalidConfig（坏配置的诊断词）承载未选择模型**：那是 scheme 类配置诊断的文案面，引导方向（去设置页修配置）与「去菜单选模型」不同。**否决**——专用类别加专属文案。
- **前端派生并传递回填键**：派生逻辑双点（前后端各一处）就是漂移面。**否决**——后端单点派生加无参读取。
- **内置回填另开一张表、或配一个清除命令**：同一张表、同一写入点已经够用；清除行退役后没有任何调用方。**否决**——同表，键带保留前缀。
- **保留内置模型维的「默认（推荐）」清除行**：内置没有 CLI，「默认」只是钉选模型的化名，可空之后化名还会是空的；清除等于下一轮拒绝，无人想要。**否决**——清除行退役，回到钉选模型走选中它的合成行。
- **端点不符时只清模型、保留强度**：会渲染出「无模型的强度」的怪态，强度本就不独立于模型。**否决**——整对按未选择。
- **前端传端点身份、或 set 的 wire 增加身份字段**：wire 多一个字段就多一处可被伪造的归属；身份是后端读活跃档案得到的事实。**否决**——后端盖章。
- **bump format_version 迁移存量 recipe**：serde default 已能表达「缺字段 = 无身份」，迁移买不回任何语义。**否决**。

## Consequences

- **校准 ADR-0007**：Consequences 的「v1 默认 Sonnet 级」读作交互层的初始默认（预设与新建档案的骨架预填），不再是对档案的必填要求、也不再是后端读取路径的兜底值；「用户可切顶级（Fable/Opus）/Haiku」与「加提供商是配置而非重写」两句不变。见 ADR-0154。
- **校准 ADR-0100**：Decision 1 的「per-adapter 记录」读作按运行时分记——外部通道按适配器 id、内置运行时按端点身份，同住一张表、同一写入点；Decision 2 的「跨适配器不迁移」对内置读作「跨端点不迁移」；Decision 3 的「清除行置空该条目」与 Why 3 的「一键显式撤销」对内置模型维不适用——内置模型维无清除行，条目不可经菜单清空（已接受的损失），强度维照旧；悬空保留（Decision 4）不变。见 ADR-0154。
- **校准 ADR-0102**：Decision 3 的「内置运行时 := 空（内置不消费姿势）」读作「内置运行时 := 活跃端点的回填条目」；Decision 1 的「两者由构造保证同源」与「无需归属字段或条件恢复」对适配器轴不变，内置轴的姿势对另带端点身份——端点在 app-config 里移动时会话零写入也漂移，构造同源覆盖不到；Considered 否决的「resume 回落默认运行时 + 姿势对附带归属适配器条件恢复」只针对适配器轴，仍然否决。见 ADR-0154。
- 新增专用的永久失败类别（未选择模型）：key 门在前，它只在「有 key、无模型」时出现；轮次终局词汇、前端呈现与双语 catalog 同步新增该类别，提取面板新增对应的失败面。
- 设置页的模型字段可选：必输校验退役，「自定义」预设选中即清空模型；预设默认模型与新建骨架预填不变。连接预检在无模型时跳过无法进行的 turn 探测，只结论端点可达且 key 被接受（连通、未列出模型），不断言能否服务轮次。
- 接受的代价：内置回填条目不可经菜单清空；存量内置会话（姿势对不带端点身份）resume 后按未选择处理，需要重新选择一次——持久值不丢，但不会被注入。
