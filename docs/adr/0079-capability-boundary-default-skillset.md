# 能力边界:降为默认技能集语义,开放扩展

## Decision

ADR-0017 的能力边界（SQL/DuckDB 原生为界，预测 / 机器学习 / 语义文本分类拒绝）从**系统不变量**降为**默认技能集的默认行为**：未挂载任何技能的会话保留完整 ADR-0017 行为（诚实拒绝 + 给出 in-scope 替代）；用户可经自定义技能与外部 MCP 工具（ADR-0076 工具 / 技能）扩展任意能力，边界语义降为每技能。app **不对用户挂载的工具/技能做能力类审计**（local-first 用户主权）。

## Context

ADR-0017 把 v1 能力边界定为系统不变量：越界请求诚实拒绝。ADR-0076 引入用户可配置的 MCP 工具与技能后，硬边界与扩展开放性相悖：维持硬边界需 app 识别任意第三方工具的能力类（是否 ML 类），该审计无可靠技术手段，且与 local-first 用户主权相悖。

## Why

1. **诚实拒绝的价值在默认体验**：不挂载的用户得到与 v1 完全一致的边界保护；不变量地位降，默认行为不变。
2. **能力类审计是死路**：第三方工具能力不可声明、不可推断；白名单 curated 引入「谁审」治理成本。
3. **边界降位后强制点挪到「哪些工具存在 + 分级审批」**（ADR-0080）——可控、用户可感知的机制。
4. **CONTEXT.md 首段同步改写**（「默认能力以…为界；用户可自行扩展」），词汇表与决策一致。

## Considered options

- **硬边界维持（能力类审计）**：无可靠技术手段，策展成本高，与用户主权相悖。**否决**。
- **白名单 curated 开放**：治理负担 + 扩展自由度半失。**否决**。
- **开放且无默认边界（废止拒绝）**：默认体验退化——越界请求触发无效工具调用尝试而非诚实拒绝，违 ADR-0017 诚实原则。**否决**。

## Consequences

- **取代 ADR-0017 的系统不变量地位**：拒绝行为保留，降为默认技能集语义；「诚实拒绝 + 替代建议」交互模式不变。
- **校准 CONTEXT.md 首段**：已改写为「默认能力…用户可经技能/MCP 扩展」。
- 边界强制改依 ADR-0080 分级审批；默认技能集下越界拒绝骑 textual 终局答复（ADR-0077）。
- **被 ADR-0108 校准**：扩展路径增加用户注册的 CLI 工具为第三成员；本 ADR 的「外部 MCP 工具」措辞读作外部工具（MCP 服务器与 CLI 工具）；「边界语义降为每技能」校准为每技能 / 每工具；默认行为不变。
