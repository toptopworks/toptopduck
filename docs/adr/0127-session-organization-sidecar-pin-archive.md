# 会话组织态：侧车索引承载置顶与归档

## Decision

1. **置顶与归档是 shell 层组织态，落 `sessions_root/index.json` 侧车文件，键为会话目录 uuid。** 组织态与会话内容分家：`.duck` recipe 是内容真相（ADR-0034 每终态回合原子重写、ADR-0036 不存时间戳），组织态的高频变更不触碰它——不重写 recipe、不污染 mtime、不经单写者门（ADR-0035）。侧车形如 `{"format": 1, "pinned": [...], "archived": [...]}`，写入复用 `save_atomic`。键取目录 uuid 而非绝对 `duck_path`：会话身份随目录（ADR-0089），侧车随 sessions_root 整体迁移（备份、换机、未来根搬迁）不失效。

2. **读取面合并进 `list_sessions`，服务端裁剪与排序。** 扫描后与侧车 join，`SessionMetadata` 增加 `pinned`、`archived` 标志；返回序为置顶（数组序）在前、未归档按 mtime 降序（现状序）随后；归档行默认不返回，`includeArchived` 参数供归档视图拉取。托盘（ADR-0125）与搜索（ADR-0072）消费同一响应，归档自然不可见；搜索零改动，托盘在消费前按 mtime 重排以维持 ADR-0125 的近因序（置顶块是侧栏语义，不进托盘）。侧车缺失按空集合静默降级（同 `scan_sessions_dir` 的 NotFound 惯例，首启不告警），不可读或损坏按空集合降级并 `log::warn`，列表照常；扫描时丢弃既不在扫描集内、目录也已消失的孤儿键，侧车有界且自愈——下一次成功写入覆盖损坏文件。

3. **写入面为两条专用命令，互斥在后端单次原子写内完成。** `set_session_pinned` 与 `set_session_archived` 对齐 `rename_session` 的形状（根内路径守卫、类型化错误、日志约定）。归档 = 同一次写内从 `pinned` 移除并加入 `archived`；置顶已归档会话为幂等 no-op（归档视图不暴露置顶动作，后端兜底）。未知 uuid 幂等 no-op——集合移除不可能引入未知引用，无需存在性探测。同进程内的全部侧车读-改-写（扫描清扫、置顶/归档、打开解档）经一把进程级互斥串行化：整文件原子重写下并发的读-改-写会以最后写者覆盖并发的另一方（扫描清扫恰逢置顶即丢置顶），串行化并在锁内复核剪枝候选的磁盘存在（扫描快照陈旧不误剪活键），消灭该窗口；这是进程内锁，不是 ADR-0035 的单写者门，侧车从不跨进程共享。

4. **打开即解档。** `open_duck` 绑定成功后查侧车，命中 `archived` 则同一次写内移除。文件选择器、系统关联打开等绕过侧栏的入口因此自动恢复会话，「打开中但已归档」的矛盾态不可达；恢复入口唯一性的例外仅此一条，且方向为用户主动使用。

5. **置顶序为 MRU 头插数组序。** 置顶 = 头插，取消 = 移除；数组位置即展示序，不存时间戳（ADR-0036 精神：数组位置是时间序的充分代理）。无上限、无置顶区内手动拖序。

6. **归档保留一切内容状态。** 目录不删、recipe 不动、mtime 不变；恢复后按 mtime 回到未归档序列的原位，零额外状态。删除的唯一破坏性出口语义不变（ADR-0060）：归档小节内新增的删除动作沿用其强确认与先关后删契约，既有删除入口不在本决策范围内。

7. **归档可见性为侧栏内开关，不持久化。** 默认隐藏；开启后主列表下方附加灰显归档小节（行不可激活，动作限恢复与删除），主列表保持不变。开关每次启动重置——归档的产品语义是「从浏览面消失」，可见态不粘滞。搜索（ADR-0072）不含归档会话，与侧栏默认视图一致。

8. **失败面跟随既有惯例。** 写命令失败走 shell 错误面（与 delete/rename 同路）；前端不做乐观更新——本地 IPC 毫秒级往返，mutation 成功后按 ADR-0068 epoch 重拉收敛。

## Context

会话是自包含目录（`{uuid}/session.duck` + `assets/`，ADR-0089），`list_sessions` 扫描目录派生 `SessionMetadata`（路径即身份，rename 不动路径），排序依赖文件系统 mtime。侧栏以日历分组或平铺呈现单一时间序列，无任何组织态；会话多后重要会话沉底、休眠会话常驻，置顶与归档是缺的组织面。应用为单窗口单进程本地形态，无多端同步与协作面，收敛机制即 ADR-0068 的 epoch 重拉。

## Why

1. **组织态与内容态分域是成本结构决定的。** 归档一个会话若须重写 `.duck`，则组织动作要过单写者门、要与回合持久化竞争、还会把归档时刻伪装成内容变更（mtime 重排）。侧车把这三项成本一次消掉。
2. **uuid 键是迁移稳定性的唯一选择。** 绝对路径键在 sessions_root 搬迁后整体失效；uuid 与目录同生共死，是扫描 join 的天然键。
3. **服务端裁剪让「归档=消失」语义三面一致。** 侧栏、托盘、搜索各有一个「归档会话漏网」的入口就是三处缺陷；在数据源裁掉比在每个消费方过滤便宜且不可漏。
4. **互斥进后端单次写消灭状态机分支。** 归档摘置顶若由前端两次调用组合，中间态（已归档仍置顶）可被刷新窗口观察到；单次写让该状态不存在。
5. **原位灰显被否决的依据是排序模型。** 原位方案的价值在保持用户手动整理的位置（归档不丢位）；本应用排序为纯 mtime、无用户整理面，原位散布只剩浏览噪声，集中小节的总览-恢复-删除动线更短。

## Considered options

- **recipe header 加组织字段**：组织变更重写 `.duck`，过单写者门、污染 mtime、内容域混入组织态。**否决**。
- **归档即迁移目录（如 `archived/` 子目录）**：路径即身份，移动断开 `open_duck`、托盘与既存引用。**否决**。
- **组织态进 AppConfig**：应用配置与会话数据域耦合，且不随 sessions_root 迁移。**否决**。
- **`duck_path` 绝对路径作侧车键**：根搬迁即整体失效。**否决**。
- **泛化单命令 `set_session_flags`（部分更新语义）**：互斥退化为调用方两次调用编排，中间态可观察。**否决**。
- **归档原位灰显 + 三态过滤器**：价值依赖用户手动排序的位置保持，本应用为纯 mtime 序。**否决**。
- **设置页归档管理**：恢复动线深埋、一个状态两个家。**否决**。
- **打开已归档会话时拒绝或保持归档**：拒绝挫败感最强；保持归档制造「活跃但不可见」矛盾态，破坏 `activeId ∈ sessions` 直觉。**否决**。
- **前端乐观更新 + 失败回滚**：为远端延迟付的复杂度，本地 IPC 不存在该延迟。**否决**。
- **自动归档（超期完成会话）**：无产品输入，留待真实反馈。**否决**。

## Consequences

- **校准 ADR-0072**：搜索结果「空查询显示全部」的集合外延读作不含归档行——归档会话不可经搜索到达（本决策 Decision 7）；搜索字段与截断窗口机制不变。
- `index.json` 是组织态单点：损坏降级为空集合（置顶归档全消失但不影响列表可用），下一次组织写入自愈；用户可感知面仅为置顶丢失，无数据损失。
- 侧车键与目录 uuid 的关联在扫描 join 时天然免疫外部删除（孤儿键读不到行）；GC 在扫描时顺手完成，侧车体积有界。
- 恢复后回 mtime 原位意味着归档不保留「归档前排序」概念——本就无排序可保。
- 置顶数组已是有序结构，未来手动拖序只需换写路径，存储形状不变。
- 搜索模态与托盘的实现不需知情归档存在；未来新增列表消费方时默认即正确。
- 归档会话的 HoverCard 元数据卡保持可用（只读查看不等于激活）。
