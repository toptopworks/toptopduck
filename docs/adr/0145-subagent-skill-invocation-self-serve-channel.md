# 子智能体技能调用：自取通道开放与归属挂父轮

## Decision

1. **子面减集收窄为仅委派工具族。** 子智能体工具面 = 全量网关面减全部委派工具；`invoke_skill` 与 `read_skill_file` 随主表生存（issue #985）。挂载条件构造性镜像主面：两者仅在发现快照非空的轮次进主表，减集继承之——零技能会话的子面照旧无此二工具，零常驻成本。逐技能闸门沿用机器级启用轴，与主面完全同构（免审批继承）；agent 定义的技能名标记通道保留不变，降格为作者确知的确定性快路径。

2. **发现索引进子上下文。** `subagent_preamble` 装配时一次性并入发现快照索引块——主面同款字节（name + description、同 360 字符描述钳制），追加在绑定注入体之后。子智能体知道能调什么，`invoke_skill` 不是名字盲调；快照外中途启用的技能对子不可自动发现，与主面 agent 的自发现同构（下会话生效）。

3. **归属 = 父轮 pending + 名条渲染。** 子智能体的 `invoke_skill` 调用经共享 dispatch 核记入父轮 pending 调用表——`read_skill_file` 的读门「快照 ∪ 本轮 pending」零改动组合，子调用的附件当轮可达。持久化侧落全量 `SkillInvocation` 记录（正文 + 调用时点哈希）；轮次窗口装配对子来源记录只渲染名字标记、不渲染正文——正文经子自己的工具结果进了子的上下文，重渲染进父窗口是父模型从未消费过的重复字节；父 agent 需要正文时自己免审批调一次，自取双向闭合。`actor` 维持 user/agent 二值，归属由新增可选字段 `via_subagent`（serde default + skip_serializing_if）承载——前向兼容，不升 format_version。

4. **深度 1 维持。** 委派工具族的物理排除不变：递归结构性不可能、子步帽与同批帽不变。多步委派由父编排链覆盖（父本可同轮多次、跨轮顺序委派）；`sub_face` 每轮预计算、全委派共享的结构红利保持。

## Context

ADR-0119 Decision 4 维持子智能体对调用元工具的排除，其理由链是：调用虽不再是会话级突变（旧排除理由消亡），但「开放给子智能体是新增能力面且其技能需求已有定义标记通道覆盖」。标记通道（ADR-0117 Decision 2）在装配时以 preamble 反引号标记与注册名单做交集、命中的技能正文一次性注入子上下文——它是作者的显式声明通道，不是运行时的自取通道。两个结构性缺口随之存在：其一，委派任务需要某技能而定义未挂标记时，子无路径取得正文（漏挂 = 委派死路，无自愈）；其二，活体不协调——标记注入的技能体指引读取 `references/` 等附件时，读门以「未调用」拒绝并把修复指向 `invoke_skill`，一个子面上不存在的工具。社区 harness 的子智能体技能面实况：pi 的子进程重扫技能目录（索引进 system prompt、控制靠 agent 定义工具白名单）、dsh 的 scope 分层注册表（scope key = agent 本身，进程内同构）、opencode 的子会话默认挂 skill 工具（Permission 逐技能断言、深度默认 1 可配）——ambient 挂载是独立实现收敛出的共同极形，dsh 与本仓同为进程内 + per-agent scope 架构。

## Why

1. **消灭「漏挂 = 死路」失败模式**：标记通道是作者确知快路径，但其失败模式（漏挂无自愈）只有运行时自取通道能结构性消灭——opt-in 形态复活同一失败模式，无条件挂载（ambient）是收敛极形。
2. **读门组合性白拿**：子的调用挂父轮 pending 即自动进入「快照 ∪ pending」，附件当轮可达零新机器——归属选父轮的载荷理由。
3. **审计零新面**：子的调用经共享 dispatch 核，trace、启用轴、免审批语义 identical by construction；窗口名条骑既有渲染词汇（【技能调用】帧），无新 UI。
4. **前向兼容零断点**：可选字段 + serde default 使旧版本读新文件语义不变，不升 format_version——新增 actor 变体则旧版反序列化直接炸。
5. **深度 1 的理由重立而非继承**：ADR-0119 的技能排除理由随本 ADR 消亡，维持的依据改为父编排链覆盖多步委派与预计算共享红利——理由与裁决同寿，翻转触发器（子须自主再分派）显式留尾。

## Considered options

- **per-agent 工具 opt-in 白名单**：作者漏 opt-in 时子仍无自取通道，复活同一死路失败模式；白名单轴与 ADR-0117 的既有裁决（「纯收窄轴且权限面已由审批同构覆盖」）相抵。**否决**——无条件挂载（Decision 1）。
- **挂工具但不进发现索引（名字盲调）**：模型不知何可调，查无此名的自纠信号无目录可列。**否决**——索引进子上下文（Decision 2）。
- **新增 `Subagent` actor 变体**：serde 枚举新变体使旧版本反序列化炸，须升 format_version 走迁移链；归属是记录的注脚不是语义分叉。**否决**——可选 `via_subagent` 字段（Decision 3）。
- **子来源记录正文照渲染进父窗口**：父模型从未消费过的字节重复进父上下文，且子的探索性长链正是委派要隔离的对象。**否决**——名条渲染，父要正文自调（Decision 3）。
- **per-skill 可调用策略闸门（dsh 的 `modelInvocable` 形）**：本仓启用轴已是单一机器级真源，加策略层 = 第二真源。**否决**——沿用启用轴（Decision 1）。
- **顺带开放深度 > 1（opencode 的 `subagent_depth` 旋钮形）**：解锁一个未建机器（路径归属、步帽组合语义）等于解锁未定义行为；无场景压着。**否决**——维持深度 1，旋钮记为留尾票的实施参照（Decision 4）。

## Consequences

- **校准 ADR-0117**：Decision 4 的「减全部委派工具减 `activate_skill`」读作「减全部委派工具」——`activate_skill` 的继任者 `invoke_skill` 不再在减集；Decision 2 的标记注入降格为作者确知快路径（装配语义、交集提取、失效跳过警示全部不变）。
- **校准 ADR-0119**：Decision 4 末句「子智能体维持排除（其技能路径 = agent 定义的技能名标记注入，ADR-0117 不变）」退役；其 Why 6 与 Considered「子智能体同步开放调用」的否决理由（能力增益无现实场景）被漏挂死路与活体不协调翻案，免审批、快照条件挂载、自纠信号语义全部维持。
- **CONTEXT.md 校准**：「子智能体」词条（工具面减集、技能调用归属）与「agent 定义」词条（标记通道定位）改义。
- **委派工具描述随改**：「no skill activation」措辞随开闸失效退役。
- **留尾**：子须自主再分派的场景出现时另开票评估深度旋钮（opencode 的 `subagent_depth` 先例）；agent 定义加 per-agent 工具白名单轴需求出现时再议。
