# 多晋升轮次表示:outcome 与 recipe 携带有序晋升链,primary 派生为链尾

## Decision

一个 result 轮次（ADR-0077「result = 本轮产出一或多个晋升」）的 outcome **携带按晋升顺序的完整晋升链**——每个晋升是一个中间结果，各得一个按晋升顺序编号的 `result_N`（ADR-0022），链非空。**主结果（primary）不是存储字段、不是领域概念，而是派生属性 = 链尾**：loop 的终止形态是「物化若干次 → 就最后一个产物写终局文本」，故链尾即终局答复所引用者；展示层取主推时读 `promotions.last()`，由唯一调用点保证一致。

表示层三处同构：

1. **轮次条目**（thread / 内存历史）：一轮一条 `Turn` 条目（守 ADR-0028 不变量 1「恒可见」与不变量 2「恒占 N=20 一槽」），其 result outcome 内携整条晋升链。
2. **recipe**：一轮仍是一条 `RecipeEntry::Turn`（不扇出），其 Materialized outcome 携整条晋升链、每晋升各带自己的 stale；`productive_chain` 按晋升展平（每晋升一个 `ProductiveTurn`），重放顺序 = 轮次序 × 晋升序，对「链内后序晋升派生自前序」天然拓扑有效。recipe `format_version` 升 3，配 v2→v3 单向迁移（沿 ADR-0082 机制）。
3. **窗口装配**：「在窗内」是**轮次级**属性——凡属近期 N=20 轮次的晋升（含前序）一律按窗口内处理、同带样本；数据集块本就走工作集全枚举，前序晋升天然可被后续 SQL 引用。

stale 级联（ADR-0041）与编号（ADR-0022）按 `result_N` 的派生关系运作，本就不分轮内轮外，与上述表示零冲突：链内 result_2 派生自 result_1 时两者同级联失效、同被 `productive_chain` 跳过；来源独立者各判各的。

## Context

ADR-0077 把轮次契约从「恰好一条 SQL」改为「0 或多次工具调用」，并校准 ADR-0028「result = 本轮产出一或多个晋升」；CONTEXT「轮次」术语亦明文「一或多个晋升」。但该契约只定了 outcome 的**基数**（≥1 晋升），未定其**表示**：outcome 如何承载多个晋升、recipe 如何持久化、窗口如何枚举、primary 如何定义，均付之阙如。内置循环接线（取代单 SQL 编排器）使一个提问天然展开为「筛 → 聚 → 总」多次物化，表示层欠账遂暴露：若 outcome 只承载单个终局晋升，前序晋升虽进工作集却不入历史 / recipe——可被后续 SQL 引用，却在对话历史、recipe 与前端无踪迹；resume 的 `productive_chain` 只见链尾，派生自前序者重放即断，工作集与可见历史发散。

## Why

1. **晋升链是 result outcome 的本体，非附件**：ADR-0077 原话是「一**或多个**晋升」，链是这个 outcome 之所以为 result 的全部。把它拆成「单主结果 + 旁挂前序」等于在表示层重新引入 ADR-0077 已废止的单 SQL 心智，前序晋升仅存于工作集、不入历史 / recipe，工作集与可见历史发散、resume 重放断链。
2. **primary 派生而非存储，消除非法态**：链尾即 primary 由 loop 终止形态保证（物化后才写终局文本，文本引用最后产物）。若 outcome 既存晋升链又存 primary 索引，就有「索引与链尾不一致」的非法态可写；令 primary 恒为 `promotions.last()` 的派生，一致性由唯一调用点承载。
3. **recipe 一轮一条目守住 ADR-0028 一轮一槽**：扇出成多条 `RecipeEntry::Turn` 会让持久化的对话历史把一个提问显示为 N 张卡片、占 N 个 N=20 槽，违反不变量 1（一条）与 2（一槽）；一轮一条目 + outcome 内携整链，展示保真与 resume 展平两得，且一轮的多调用执行轨迹（ADR-0078）不必劈到多条。
4. **在窗内是轮次级属性**：窗口以 N=20 轮次计槽，一个多晋升轮次整体在窗内，其全体晋升同属窗口；按单点（primary）判定会把同轮前序误降为窗口外、只发 schema 不发样本，削弱最常被引用的中间结果的可见性。

## Considered options

- **强制单晋升（loop 边界拒绝第二个物化）**：把多晋升塞回单 outcome 表示。违反 ADR-0077「一或多个晋升」与「筛 → 聚 → 总」多步分析形态，退回已废止的单 SQL 心智。**否决**。
- **一个轮次扇出成多条时序条目（每晋升一条 `Turn` / `RecipeEntry::Turn`）**：resume 展平虽等价，但持久化历史与 N=20 窗口把一个提问算作 N 条、N 槽，违反 ADR-0028 不变量 1/2，且把一轮的多调用执行轨迹（ADR-0078）劈到多条。**否决**。
- **outcome 存单主结果 + 旁挂前序列表**：前序不入 outcome 本体，工作集 / 历史 / recipe 三处对「哪些是本轮回结果」各说各话，工作集与历史发散、重放断链照旧。**否决**。
- **primary 显式存储（outcome 带 primary 索引 / 字段）**：引入「索引须等于链尾」的冗余不变量，存写两侧皆可构造非法态；派生即可，无需存储。**否决**。

## Consequences

- **校准 ADR-0077**：补「result = 一或多个晋升」欠下的表示层——outcome 携按晋升顺序的晋升链，primary 派生为链尾。
- **校准 ADR-0028**：result（A 类）轮次的 outcome 内携整条晋升链；一轮一条目、一槽、编号按晋升顺序（ADR-0022）三不变量不变，仅 A 类 outcome 的内部基数明确为 ≥1。
- **校准 ADR-0036 / 延伸 ADR-0082**：recipe `format_version` 升 3，Materialized outcome 由单 reference_name 改为有序晋升列表（各带 stale），配 v2→v3 单向迁移，沿用 ADR-0082 的单向迁移机制。
- **延伸 ADR-0041**：stale 锚点落到单个晋升（链内各晋升各带 stale），级联仍按 `result_N` 派生关系、不分轮内轮外。
- **校准 ADR-0023**：在窗内判定为轮次级——近期轮次的全体晋升（含前序）同带样本；数据集块走工作集全枚举不变。
- **前端镜像**：TS 侧 result outcome 镜像同携晋升链；thread 渲染 primary 主位、前序折叠 / 弱化（沿 ADR-0078 rail 恒显终局、细节按需展开的哲学）。渲染细节为 UX 子决策，契约层只保证晋升链可区分。
- **未决（实施期）**：晋升链在 outcome / recipe 的具体字段命名与序列化形态、`productive_chain` 展平实现、前端折叠区交互。
