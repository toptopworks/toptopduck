# 技能生命周期收敛：对话蒸馏创建与外部化编辑

## Decision

1. **创建通道收敛为对话蒸馏 + 导入。** 模型面新增受治理元工具 `create_skill`（对齐 `invoke_skill` / `read_skill_file` 命名族），参数为整串 `skillMarkdown`。服务端 parse 提取 `name` / `description` 分字段校验（typed reject），落盘原样保留未知 frontmatter 字段（消费端只取已知键，未知键按 ignore 语义）。整串形态支持从外部生态直接粘贴现成 SKILL.md 全文创建。应用内创建表单退役，设置面不承担创建职责。

2. **编辑通道外部化。** 应用内不提供技能编辑表单（编辑 drawer 随创建表单一并退役）。技能详情提供所在目录的路径链接，点击经系统文件管理器打开，编辑由外部工具完成——技能目录形态含附属文件（references / scripts 等生态常态），表单只能表达 frontmatter 与 body 三字段，应用内编辑面天然不完整。外部变更经既有扫描快照与新会话 seed 再发现。行级治理保留：启停（ADR-0118 启用轴）与删除。

3. **治理走网关审批卡逐次确认 + 会话级「始终允许」。** 信任语义按 ADR-0080：始终允许不进 recipe、resume 归零。审批按既有审批模型实体落地：工具标识 `ToolKey { builtin, create_skill }`、操作类别 `OperationKind::Write`。创建落盘跨会话存在，且 SKILL.md body 是未来提示注入源，非瞬态操作——不适用 `invoke_skill` / `read_skill_file` 的直服先例。

4. **生命周期落点：入注册表默认启用，不改写会话发现快照。** 创建只落注册表与启用轴（ADR-0118），不动当前会话已凝固的发现快照（ADR-0119 快照会话级不可变）——新会话经启用全集种子自然可达，当前会话内经调用通道按名即达（ADR-0119 快照外语义），亦即建后测试闭环的执行通道。与用户手工创建 / 导入的技能生命周期无特权差异。

5. **首版仅 create，无 update。** 重名以 typed reject 报错由模型自纠重试。修订在模型面 update 通道缺位期间 = 模型产出修订版文本，用户经路径链接在外部编辑器替换；模型面 update 通道留待独立裁决（审批须带 diff 展示）。

6. **审批知情面复用附件通道。** `skillMarkdown` 全文以附件项在审批卡按需展开。截断式预览被否——它使批准基于不完整信息，劣于全文可见。

7. **产物边界单 SKILL.md。** 模型面创建止步单文件；附属文件由用户在外部目录自行补充（`read_skill_file` 可读既有附属文件）。模型面与人工面的产物边界一致：附属文件均由外部文件系统承载。

8. **内置教学技能 `skill-creator`。** 名字沿用跨生态通名，用户导入同名技能时 shadowing 语义让导入版生效。description 须防 undertrigger（自举原则：教学技能自身的触发条件就是其教学质量的示范）。无 CLI 伴随（ADR-0120 伴随可选项），auto-include 进每会话索引。正文 = SKILL.md 格式规范 + 蒸馏四问（做什么 / 何时触发 / 输出格式 / 从会话史提取）+ description 工程 + 测试提示轻闭环（教模型建完后建议少量测试提示，经 Decision 4 的按名调用通道执行）。评分 evals 基建不建——技能产物是 prompt fragment，非可断言输出。

## Context

技能的创建与编辑目前走设置面表单（创建 / 编辑共用 drawer，后端为分立三字段命令），模型面仅有只读的 `invoke_skill` / `read_skill_file`。两个事实推动收敛：其一，技能正文的自然来源是会话中已验证的指令——让用户在表单 textarea 里从零手写 body 与指令来源脱节，由模型从会话蒸馏起草才是顺流的工作形态；其二，外部生态已趋同于「创建入口在对话、教学由内置技能承担、编辑靠系统工具」的形态。本产品为 GUI 应用，agent 不具备用户技能库的裸文件写权，蒸馏落盘必须走治理通道。

## Why

1. **模型起草与治理落盘的唯一交集是受治理专用工具。** 内容源在会话（模型起草），落盘目标在用户技能库（需审批与知情）——通用文件工具缺治理面，表单缺内容源。
2. **整串参数是生态互操作接口。** 现成 SKILL.md 全文贴入即建；落盘保真让技能在生态间无损往返。分立三字段与退役中的表单形态耦合。
3. **系统编辑器是完整编辑面。** 附属文件在表单中不可表达；扫描快照与新会话 seed 已提供外部变更的再发现，应用不重复实现编辑器。
4. **单文件边界让模型面治理最简。** 多文件创建会把审批卡复杂度与教学面同时膨胀，而外部文件系统已覆盖该需求。

## Considered options

- **模型经通用文件工具裸写 SKILL.md**：绕过审批治理，body 作为未来注入源无知情面。**否决**。
- **分立三字段参数（name / description / body）**：与退役中表单同形；无法承接整串粘贴；落盘丢未知 frontmatter 字段。**否决**。
- **截断式审批预览**：使批准基于不完整信息。**否决**——全文经附件通道可见。
- **首版并入 update 工具**：修订审批需 diff 展示设计，未经独立裁决。**否决**——先收窄范围。
- **评分 evals 基建**：技能产物是 prompt fragment，非可断言输出，与带断言产物的 evals 场景不同构。**否决**。
- **应用内编辑面增强（支持附属文件）**：重复实现系统编辑器，能力受限于应用内实现范围。**否决**。
- **创建即改写当前会话发现快照**：违反快照会话级凝固语义（ADR-0119），且与手工创建 / 导入技能的生命周期不对称。**否决**——新会话种子自然可达。
- **附属文件创建通道**：治理面与教学面复杂度双涨，外部文件系统已覆盖。**否决**。

## Consequences

- 创建与编辑均不依赖应用内表单形态，与「技能 = 文件系统资产，应用只做治理与通道」的定位一致。
- registry 需新增整串入口：校验 / 重名 / 失败清理契约复用既有实现，落盘走原文；既有分立入口随表单退役删除。
- `create_skill` 需双面广告：内置工具表与 gateway `tools/list` 同步注册。
- 既有分立三字段命令与 drawer 随表单退役删除；退役落定前创建 / 编辑两通道并存。
- 修订闭环在 update 工具缺位期依赖人工经外部编辑器替换；教学技能的测试提示闭环依赖快照外按名调用语义持续成立。
- **校准 ADR-0118 Decision 6**：设置面作为唯一管理面的职责收窄——创建移交对话蒸馏通道（`create_skill` 元工具）、编辑移交外部系统工具，管理面保留列表、启停与删除。
