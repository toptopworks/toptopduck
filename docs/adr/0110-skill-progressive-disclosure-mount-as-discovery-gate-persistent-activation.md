# 技能渐进披露：挂载即可发现，激活态持久注入，免审批激活

## Decision

1. **挂载降为可发现集闸门，元数据索引取代全文注入。** 挂载不再注入正文：挂载技能仅以元数据（`name` + `description`）随轮次装配常驻，构成该会话的**可发现集**（即挂载集）；元数据索引只列挂载而未激活者。卸载退出可发现集。挂载保留每会话用户闸门地位——哪些技能对一个会话可见仍由用户决定；内置技能的自动挂载语义保留（见 Decision 7）。

2. **激活态为会话级持久状态，正文持续注入。** 激活集 ⊆ 挂载集；激活技能的正文随每轮装配持续注入（渐进披露第二层），直至卸载。激活是权威会话状态，记入 recipe timeline（Decision 5）。「一次性工具结果进轨迹」被否决——轨迹不进远窗，一次性注入在长会话中必然被窗口化磨掉。

3. **激活信道 = 网关元工具 `activate_skill(name)`，免审批。** 工具面由网关一处装配：内置运行时进程内路由、外部运行时经桥接消费同一份面（与 ADR-0105 三件套同纪律）；挂载集为空的轮次不挂 `activate_skill`（空集条件挂载同构）。激活无审批门——挂载是技能的唯一信任闸门。查无此名时把全部可发现技能名列在错误内容中返回（自纠信号，与 `mcp_invoke` 句柄失败语义同构）；重复激活幂等成功、返回正文。激活当即生效：调用结果的正文对当轮立即可见，自下一轮起正文进入持续注入——轮中激活不与当轮装配竞争。

4. **激活两方可发起，卸载是唯一出口。** 激活可由 agent（元工具）或用户（挂载列表两态）发起，共用同一状态转移。卸载级联失活，是激活的唯一出口；无独立去激活事件、无 `deactivate` 工具。

5. **记账：`RecipeEntry::Skill` 第三态 `Activate`，出处记激活集。** 事件携带发起方标记（用户 / agent）；生命周期事件族扩为挂载 / 卸载 / 激活三态，定义放宽为「用户或 agent 驱动的突变」（agent 驱动者仅激活）。`TurnProvenance.skills` 由挂载集校准为**激活集**（当轮实际注入正文者），`content_hash` 陈旧降级语义逐位继承（ADR-0086 Decision 2）。recipe format_version v5 → v6（ADR-0036 纪律：新事件变体 + 出处形状变是前向兼容断点；v4 → v5 已被 ADR-0103 轮次分组消费）；迁移对生产 recipe 是 no-op（无 `Activate` 事件存在）；旧会话 resume 后激活集为空——正文不再自动注入，直至重新激活，无降级误报。

6. **执行取提示注入侧，第三层推迟。** 执行 = agent 依激活正文行事：用技能声明的 MCP / CLI 工具经网关调用（声明性引用语义不变——所指者须已配置并启用，引用不改变配置 / 启用状态）。ADR-0086 Decision 1 的 `scripts/` 禁令维持；渐进披露第三层（技能目录附带 scripts / references / assets 的按需读取）整体推迟至未来信任模型 ADR（沙箱 + 审批 + FS 收口下的受限可读面一并裁决）；`activate_skill` 只返回正文，不携带目录结构提示。

7. **内置技能自动挂载、不预激活。** ADR-0109 Decision 6「自动进入新会话活跃技能集」校准为自动进入**挂载集**——起步即可发现，正文待按需激活（激活免审批、零摩擦），不再自轮 1 起全文常驻。内置技能的 `description` 为 app 策展的触发文案，负发现质量之责。

8. **外部运行时平权。** ACP 装配以「元数据索引块 + 激活正文块」取代全文技能块，披露层级与内置逐位一致；「由 app 在轮次装配阶段统一注入、与运行时无涉」原则在新模型下保持。

## Context

ADR-0086 确立技能挂载即全文注入：每个挂载技能的 Markdown 正文随每轮系统提示下发。注入成本随挂载数与正文长度线性增长——会话挂载数个技能后，未涉该技能的轮次也全额支付正文 token。同一税种在外部工具面已被 ADR-0105 以固定发现面摘除（广告成本与目录规模脱钩）；技能面是最后一块平铺广告区。

Agent Skills 生态的通用答案发现 / 激活 / 执行三段式 + 渐进披露：元数据常驻、正文按需、资源更按需。toptopduck 引入该模型时面对两条本域特有的硬约束：远窗窗口化纪律（轨迹不进远窗）排除一次性注入形态；网关 + 桥接使两种运行时共享受控工具面，激活得以成为工具而非文本信道。

## Why

1. **广告成本与挂载数脱钩**（0105 同一理由的技能面延伸）：元数据索引的每条成本是 `description` 量级，正文成本收缩到激活子集、且只付给真正塑造行为的轮次。
2. **挂载闸门保留**：用户对会话能力面的控制权不丢；ADR-0109 内置技能自动挂载直接平移为自动可发现；卸载级联干净。全库可发现会把不可控大目录的元数据税摊给每个会话，并摧毁既有生命周期词汇。
3. **持久注入是窗口化纪律的必然，不是偏好**：轨迹不进远窗、远窗只收摘要；一次性注入形态下激活指令在长会话中必然腐蚀（「激活过但忘了」），这是结构问题不是概率问题。
4. **工具信道而非散文标记 / 文件自读**：网关是唯一强制点，激活经工具即入轨迹、可审计；外部运行时的工具调用经桥接回网关，受控面对两种运行时同在场，无理由退化到文本信道；文件自读被 FS 收口否决。
5. **全直通审批**：挂载已是用户的有意信任行为；技能正文来源二分——用户自撰 / 导入与 app 策展内置——皆非不受信的第三方文本，激活时二次确认是对同一意图的重复表达。
6. **双 actor**：用户明确知道要用某技能时不应赌模型自行发现；与 agent 激活共用同一状态转移，仅 actor 不同。
7. **卸载唯一出口**：三态直线机（未挂载 → 已挂载 → 已激活 → 卸载级联回落）无悬空状态；激活免审批后重新激活零摩擦，「想安静但保留可发现」无真实场景。
8. **出处记激活集**：出处的职责是「该轮被什么塑造」+ `content_hash` 锚定降级检查，激活集才是那个集合；挂载集可由 timeline 折叠得出，重复记账无收益。
9. **内置不预激活**：内置技能是配套 CLI 的使用法指南，不碰对应任务类型的会话不该为它们付全文税；按需激活路径免审批、零摩擦，发现质量由策展 `description` 保证。
10. **第三层推迟**：app 无通用文件工具、`fs_acl` 纪律在案、`scripts/` 禁令在案——资源层需要自有的信任模型（沙箱 + 审批 + 受限可读面），不与披露层顺手捎带。

## Considered options

- **废除挂载、全库可发现（控制全靠激活审批门）**：用户失去每会话闸门；内置 / 用户技能混成不可控大目录，元数据税由所有会话共担。**否决**——挂载闸门保留。
- **激活 = 一次性工具结果进轨迹，正文靠对话历史存活**：轨迹不进远窗，长会话中激活指令必然被窗口化磨掉。**否决**——激活态持久、每轮注入。
- **激活时确认门（非内置弹确认、内置直通）**：挂载已是信任闸门；正文来源是用户自撰 / 导入或 app 策展，非不受信第三方文本，二次确认是重复摩擦。**否决**——全直通。
- **散文标记激活（模型输出中写激活标记、出站流正则拦截回填正文）**：该形态的存在理由是工具面不受控；本网关 + 桥接使受控面对两种运行时同在场，标记绕过轨迹与审计、且对用户肉眼可见。**否决**。
- **原生委托（技能目录软链进外部运行时原生技能目录，委托其自有技能系统）**：外部运行时不注能力面是既定姿态；FS 收口不容注册表向会话目录软链；审批 / 审计控制权旁落第三方。**否决**。
- **独立去激活（第四种事件 + 去激活工具 / 按钮）**：激活免审批后重激活零摩擦，卸载已覆盖「不要」；多一态即多一类悬空状态。**否决**——卸载唯一出口。
- **激活态不落 timeline、resume 从轨迹反推**：轨迹不是权威状态源，窗口化后可能只剩摘要。**否决**——Activate 事件。
- **出处双记（挂载集 + 激活集）**：挂载集可由 timeline 折叠得出。**否决**——只记激活集。
- **内置技能预激活（行为与全文时代逐位一致）**：三个内置技能是配套 CLI 使用法，不碰对应任务的会话每会话付全文税；激活免审批使按需取用零摩擦。**否决**——仅自动挂载。
- **第三层随本 ADR 一起做（沙箱执行 `scripts/` / 读附带资源）**：需自有信任模型，范围膨胀；`scripts/` 禁令在案。**否决**——整体推迟，留未来信任模型 ADR。
- **不升 format_version**：新事件变体 + 出处语义变是前向兼容断点（ADR-0036）。**否决**——v6。

## Consequences

- **CONTEXT.md 校准**：「技能」条目（挂载 = 可发现集）、「网关」条目（装配枚举纳入 `activate_skill` 与元工具概念）、「内置 CLI 注册项」条目（自动进活跃集读作挂载集）、新增「技能激活」条目、「技能生命周期事件」条目放宽（三态、用户或 agent 驱动、出处记激活集）。
- **校准 ADR-0086**：挂载注入语义——「挂载即全文注入」读作「元数据索引常驻 + 激活集正文持续注入」；身份（`name` 即身份）、`content_hash`、诚实降级、声明性工具引用、`scripts/` 禁令均不变。
- **校准 ADR-0109**：Decision 6「自动进入新会话活跃技能集」读作「自动进入挂载集」——起步即可发现、不预激活；不产生 Mount 事件的语义不变。
- **延伸 ADR-0105**：元工具家族新增 `activate_skill`——同一装配纪律（网关一处装配、两运行时同面、空集条件挂载）。
- **延续 ADR-0082**：recipe format_version 单向迁移（v5 → v6）。
- **留实施期**：元数据索引段措辞与位置（含 ACP 块形状）、`activate_skill` 出入参形状、挂载列表两态 affordance 与 thread 的 `Activate` 事件呈现、内置技能 `description` 触发质量复查、挂载数量大时的索引上限策略。
- **被 ADR-0111 落地**：Decision 6 推迟的第三层（附带文件按需读取）由 ADR-0111 裁决——受限读面（网关元工具 `read_skill_file`，app 代读、激活集门控、收口三件套）+ 执行文本中继（经注册 CLI 信道，无新执行基质）；「沙箱 + 审批 + FS 收口」的预判形态改写为借道消解（沙箱显式不解决）；`activate_skill` 只返回正文、不携带目录结构提示的纪律维持。
