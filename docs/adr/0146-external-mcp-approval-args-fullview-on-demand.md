# 外部 MCP 审批卡参数：预览帽为广播预算，全量按需可见

## Decision

1. **预览帽为广播预算，非内容边界。** 外部 MCP 工具调用的审批卡 summary 携带参数 compact JSON 预览，参数预览帽与卡体帽的双重截断只约束广播面；任一帽切入参数文本时，全量参数以可展开附件骑卡——与 CLI argv 超帽附件同通道、同生命周期：广播面骑附件帽内的截断副本作默认预览，审批挂起窗口经既有按需拉取命令取未截断原件，全量快照随 pending slot 释放。

2. **无条件完整可见，不遮蔽。** 全量参数在挂起窗口任意大小可见，不做脱敏——审批者签署的即是外部服务器将收到的载荷，遮蔽敏感值会重新引入盲签面；参数可含凭证等敏感值，受众为本机审批者自有面板，按需拉取不进广播面。

3. **可见性限于审批时刻。** 回合 settle 后不补全量可见：slot 释放即回退帽内副本，trace 维持截断 summary——事后全量审计是独立诉求，涉及持久化成本，另议。

## Context

审批卡各参数臂的可见性现状：CLI argv 超帽时挂全量附件；工作区写对挂 payload 附件；文件投递经命令按需拉取全量。外部 MCP 臂是唯一残缺：预览双重帽截断后，超帽尾段对审批者任何时刻不可见——trace 的 summary 与卡同源截断，excerpt 记录的是结果而非参数。恶意载荷可把关键操作藏在帽后，构成盲签面。参数预览进入 summary 本身即以「审批者须看见外部服务器将收到的载荷」为存在理由，截断与遮蔽都收窄这一理由的覆盖面。

## Why

1. **盲签面收口**：预览帽切在哪，盲签面就重现在哪——恶意载荷可把关键操作藏在帽后，收口方式与 argv 超帽附件同构。

2. **受众恒等**：附件副本与按需全量的消费者都是本机审批者自有面板，凭证等敏感值属用户自有，可见性增量严格受控于按需动作。

3. **通道复用零新面**：附件通道、挂起窗口按需拉取、快照随 slot 释放皆为既有机器，本决策只接入一个生产者。

## Considered options

- **遮蔽敏感值后展示**：与参数预览的存在理由相抵——审批者须看见外部服务器将收到的完整载荷，遮蔽重引入盲签。**否决**——全量不遮蔽（Decision 2）。

- **新建独立参数拉取通道（不骑广播）**：广播面确实零扩大，但需四层新管线；附件通道已在广播面承载同暴露等级的 argv 副本，收益不抵成本。**否决**——复用附件通道（Decision 1）。

- **全量可见设尺寸帽**：帽设在哪，盲签面就重现在哪；文件投递按需查看已是任意大小端态。**否决**——任意大小（Decision 2）。

- **settle 后 trace 补全量参数**：session 文件被可能巨大的载荷撑大，且事后审计与审批时刻可见是两个诉求。**否决**——限于审批时刻（Decision 3）。

## Consequences

- 广播面扩大一档：被截断调用额外骑一个附件帽内的参数截断副本，与 argv 附件同暴露等级。

- 前端零改动：附件展开、失败回退截断副本、状态提示全部继承既有文件投递视图。

- 挂载边界是参数文本是否完整可见，而非参数长度是否超帽——帧前缀同样消耗卡体预算，参数独立在预览帽内也可能被卡体帽切入。
