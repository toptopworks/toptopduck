# 会话引擎:按需物化——未执行 SQL 的会话不产生 DuckDB 实例

## Decision

1. **admin 引擎按需物化——会话创建时零 DuckDB 实例。** `Session` 构造不再打开内存连接；会话级 admin 实例在首次需要时物化——打开 + 应用资源上限（ADR-0005 Decision 3），一次完成、此后常驻。**首次需要执行 SQL 的点**是唯一的物化规则，全部消费方走同一个按需入口：源生命周期操作（ingest / 换源 / 删源）、内置工具执行（explore / materialize / describe / sample，无论内置运行时直连还是外部运行时经网关路由）、数据集行预览（`read_rows`）、派生源导入（ADR-0087 Decision 4）、resume 重放。不做逐调用点判断——新增消费方自动遵守。

2. **纯文本轮次不物化。** 轮次装配不再要求引擎在场：TurnDeps 持按需引擎源，工具分发在实际执行点解析连接。零工具调用、或仅外部工具调用的轮次全程不触碰引擎。空工作集上的字面量 SQL（如纯字面量查询）是合法的 explore 调用：当场物化引擎并此后持有，与任何其他首次需求无差别。

3. **物化一次，持有至会话关闭。** 引擎状态是单向转换，无空闲回收。引擎是工作集的存储本体——源 ATTACH 快照与 `result_N` 历史表都在 admin 实例中（ADR-0012 / ADR-0005）；回收等于销毁工作集，重建须重放 recipe 链（依赖源文件在场、有耗时、有失败面）。「用过 SQL 但当前空闲」的会话不在本 ADR 范围。

4. **带可重放内容的 resume 照旧急切重放。** 重放本身即首次 SQL 需求——引擎在 resume 时物化（eager 整链重放为 ADR-0034 Decision 4 的既有决策）；ADR-0035 完整性校验（源指纹 + 内容指纹）照旧在打开时当场报告成败。零源会话的 resume 无重放、全程零引擎（工作集元数据读取不触碰引擎）。

## Context

ADR-0087 将 DuckDB 从唯一引擎降为默认工具——「一个会话可能全程不使用 DuckDB」；ADR-0103 将对话 thread 确立为主交互面，外部运行时的纯文本轮次是合法的会话形态。不需要 DuckDB 的会话是既有的领域事实。

但实现上，`Session` 构造即急切打开内存 DuckDB 连接并应用资源上限；多会话并行（ADR-0027）意味着 N 个打开的会话持有 N 个独立引擎实例（每实例自带线程池）。纯聊天会话从创建到关闭挂着一套闲置引擎，不执行一条 SQL 也付足 DuckDB 的成本——而工作集恒为空的会话，该实例不承载任何状态。

两层引擎需要区分：每轮沙箱实例已经是惰性的——`try_materialize` 内按轮开启、轮末即弃（ADR-0005 的 read_* 阻断机制）；急切的是会话级 admin 实例。本 ADR 只动 admin。

## Why

1. **用才付钱。** 全程不触碰 SQL 的会话从创建到关闭零引擎实例、零线程池——这正是 ADR-0087 引入的会话群体，也是本 ADR 的动机。
2. **单一入口胜过枚举。** 物化规则只有一句——「首次需要执行 SQL 的点」；枚举触发点使规则散落，每增加一个消费方都要重新判断，漏判一处即是 panic 路径或变相急切。
3. **回收的复杂度/收益不成比例。** 按需物化的赢面是「永不碰 SQL」（全额免除）；空闲回收只服务「用过但当前空闲」，而回收销毁工作集的存储本体、重建须重放——以复杂度与失败面换薄收益（YAGNI）。
4. **急切重放保持诚实。** 完整性失败在打开时当场报告（ADR-0035）；延迟重放把失败时点推到「第 N 轮 explore」，且惰性之上的惰性要求每次执行 SQL 前先判断「重放了没 / 部分重放 / 失败重试」的账目。

## Considered options

- **枚举触发点、逐调用点决定是否物化**：规则散落，每新增消费方都要重新判断，漏判即 panic 路径或变相急切。**否决**——采用单一按需入口。
- **TurnDeps 继续持必填连接引用**：引擎被轮次装配强制在场，纯文本轮次也物化，按需物化名存实亡。**否决**——改持按需引擎源，工具执行点解析。
- **空闲回收（引擎在空闲阈值后释放、下次使用重放重建）**：回收销毁工作集存储本体；重建依赖源文件在场且有失败面；服务对象（「用过但当前空闲」）不在本 ADR 范围。**否决**——物化一次，持有至关闭。
- **连 resume 重放也延迟（先只载元数据，首次引用历史结果的内置工具才重放）**：ADR-0035 校验失败时点从打开漂移到对话中段；双层惰性引入重放状态账目。**否决**——重放即首次 SQL 需求，resume 时物化；ADR-0034 Decision 4 已在重放层否决过同形态的懒方案（部分物化状态机 + 失败散落到用户每次触碰为不诚实）。
- **每轮沙箱实例也惰性化**：它已在 `try_materialize` 内按轮开启、轮末即弃（ADR-0005），天然惰性。**否决**——范围外，只动 admin。
- **重命名 `session.duck`（去除历史命名味道）**：recipe 是文本，文件名是格式身份；重命名是零收益震荡，且波及导入/导出兼容。**否决**。

## Consequences

- **与 ADR-0089 消灭的 `None → Some` 不冲突**：0089 反对的是用户可见的持久化两态（两态 UI、save-if-bound 的 no-op 分支、崩溃丢失窗口）；引擎物化是 IPC 不可见的内部记忆化——无两态 UI、无丢失语义，转换由客观事件（首次 SQL 需求）驱动而非用户动作。形似而层次不同。
- **IPC 面零变化**：`createSession`、会话列表、thread 展示均不感知引擎状态；无两态 UI 复活。
- **TurnDeps 形状变更**：必填连接引用变为按需引擎源，全部内置工具实现在执行点解析连接，网关内置分发路径同步变更。结构性改动集中在单一接缝。
- **校准 ADR-0027**：「每会话一个独立内存 DuckDB 实例」收敛为「每会话至多一个实例」——从不执行 SQL 的会话不产生实例；「创建/销毁随会话开关」校准为「创建在首次需求、销毁随会话关闭」。物理隔离、每会话单飞行、每实例资源上限语义不变。ADR-0027 已加反向指针。
- **不变项**：ADR-0035 Decision 3 的 single-writer registry 是文件级、在 `createSession` 时获取，与引擎正交；ADR-0089 Decision 6 的空会话 close 清理走 timeline 判定；ADR-0005 资源上限语义不变——时点从构造移到物化，仍在实例打开时应用一次；会话临时目录与 `tool_output` 子目录（ADR-0087 Decision 3）照旧在会话构造时创建——文件系统准备不是引擎物化。
- **CONTEXT.md 不变**：「会话」词条的「打开时其工作集在内存中物化」对非空工作集仍成立，空工作集平凡成立；引擎是实现实体，不进 glossary。
- **留实现期**：按需访问器的具体形态、TurnDeps 按需引擎源的载体形状、「纯聊天会话全程零引擎」的回归钉。
