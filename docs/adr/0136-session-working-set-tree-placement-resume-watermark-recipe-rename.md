# 工作集：落位 per-session 树——源快照常驻、伴生结果库、resume 水印免重放、recipe 更名

## Decision

1. **上传源快照从进程临时目录迁入 per-session 树。** copy-in 落 `{uuid}/<ref>.duckdb`，快照形态与挂载机制不变——admin 与每轮 sandbox 并发只读挂载同一文件照旧（源与结果必须异库：sandbox 不能只读挂载 admin 持写锁的伴生库）。会话关闭后快照常驻树，直至会话删除。派生源快照（`assets/`，ADR-0087 Decision 4）与 SQL 引用哑副本的冻结语义不动。

2. **结果历史落伴生库 `analytics.duckdb`（实现期自 `data.duckdb` 改名：文件 stem 即 DuckDB 主 catalog 名，`data.csv` 源的引用名 `data` 会与主库撞名致 ATTACH 失败），派生缓存语义。** admin 引擎按需物化（ADR-0104 不变）时打开树内伴生库（不存在则创建；不执行 SQL 的会话仍零实例零文件）。`result_N` 驻伴生库文件，经 buffer manager 在 RAM 中作有界缓存；权威态恒为 recipe——伴生库 `_meta` 元数据行记 recipe 链摘要水印。

3. **resume 水印命中免重放，失配全量重建。** 打开时伴生库存在且水印等于当前 recipe 链摘要 → 挂树内源快照、开伴生库、跳过整链重放——零源文件重读、零结果 SQL 重算。源完整性校验照查，源消失或漂移在命中路径不再阻断，降级为「源已变更或不在场，工作集为 ingest 时快照」提示；重放路径的 re-link 与阻断语义不变。伴生库缺失/失配/版本不识 → 删除后走既有重放路径**原样**重建，重建写穿进新建伴生库并盖水印——存量纯 recipe 会话零迁移代码经此获得伴生库与树内快照。水印在 recipe settle 时加盖；recipe 写盘与水印写库两文件非原子，崩在中间 → 下次打开失配 → 一次全量重建，良性。clean close 执行 CHECKPOINT 收拢 WAL。

4. **sandbox 与资源上限机制不动。** sandbox 维持每轮内存实例；结果经 Value mirror 装载、源经只读挂载的既有机制不变；`memory_limit` 与 threads 的施加通道不变——文件连接下 buffer manager 自带逐出，工作集存储不再有不可逐出面。

5. **recipe 更名 `session.duck` → `recipe.json`。** 新会话写 `recipe.json`；列表扫描、打开、导入导出对话框对双后缀 forever 接受——旧名文件不迁移、不做原地改名。wire 字段 `duck_path` 更名 `recipe_path`，前后端同 PR。

## Context

现状机制：上传源经 copy-in 落**进程临时目录**的 `<ref>.duckdb` 快照，admin 与每轮 sandbox 只读挂载（页可逐出）；`result_N` 历史是 admin **内存主库**的 base 表（不可逐出），并按轮整体镜像进 sandbox；临时目录随进程消亡，故 resume 只能重读原文件 copy-in + 按急切重放链整链重算 SQL（ADR-0034/0035，可见进度、诚实断点）。

产品事实：过 G 级大数据文件的多场景处理是主形态常见负载，源文件置于共享位置、多会话各自 ingest 复用。该负载下重放成本 = 全量重读 + 全量重算，且会话可用性绑定源文件在场——resume 不可持续。

recipe 是 JSON 文本（`.duck` 为历史命名）；树内即将并存真数据库文件，后缀歧义从理论变现实。

## Why

1. **resume 即开即用。** 命中路径的打开成本从「全量重读源 + 整链重算」降为「开两个文件」；过 G 源的分钟级重放等待消失，进程重启不再对每个打开的会话重付全款。
2. **会话可用性与源文件解耦。** 源消失或漂移不再阻断打开；工作集即 ingest 时快照，随会话生命周期存活。
3. **恢复确定性。** 伴生库是持久快照，崩溃、断电、换机后的恢复不依赖当时源状态；命中路径上重放中途断裂的失败面整体消失。
4. **会话目录自包含。** 复制或移动 `{uuid}/` 目录 = 携数据的完整会话；删除会话 = 删目录一刀净。
5. **机制零新增。** 快照、文件连接、双只读挂载均为既有机制，本 ADR 只做落位与捷径；不可逐出的结果历史转为文件连接的有界缓存。
6. **命名止血。** recipe 本就是 JSON 文本，与真数据库文件并存的 `.duck` 后缀是常驻歧义源；本 ADR 已触碰同一批文件面，更名成本处于终身最低，拆开实施即同面二次改动。

## Considered options

- **单库合一（recipe 与数据同库）**：recipe 持久化换轨为库内事务，旁路 temp+rename 原子写与单写者/外部变更检测体系；会话记录背上 DuckDB 版本耦合，不再是永久可读的纯文本；存量须按文件魔数分叉双格式。**否决**——派生缓存以一行水印比较换取零波及。
- **仅迁源快照、结果照旧重放**：伴生库省掉，但结果重算与源重读同量级（大聚合对过 G 源的重放耗时与 copy-in 相当），免重放收益折半。**否决**——结果与源一起落位才是完整的 resume 捷径。
- **VIEW 直读源文件（零磁盘拷贝）**：打破冻结快照——会话中途改源文件，查询结果随之变化；指纹与 resume 独立性语义线整体作废；csv 每次查询重解析。**否决**——为省磁盘拷贝拆已裁决语义线。
- **内容寻址共享源库（同一源文件全局一份、会话只读挂载）**：跨会话共享状态违背 per-session 树隔离，引入全局 GC/生命周期/删除链新域。**否决**——多会话磁盘倍增实测成痛时独立决策，不与本 ADR 混轨。
- **`memory_limit` 全局预算协调**：跨会话共享预算的新协调面与配置域。**否决**——文件连接下各会话驻留已被各自上限封顶，实测咬人再议。
- **resume 失配增量追赶（只补失配点之后的 turn）**：须处理伴生库半截 turn 的状态机与逐 turn 对账。**否决**——全量重建原样复用既有路径，最坏付一次重放。
- **阈值化落盘（仅大文件会话 file-backed）**：双存储路径并存与阈值调参。**否决**——统一单一代码路径，按需物化（ADR-0104）已天然免除纯聊天会话的文件创建。
- **recipe 原地改名迁移**：已绑定路径被前端会话状态与 tray 载荷持有，中途改名引入路径失效面。**否决**——双后缀接受零搬迁零失效。

## Consequences

- per-session 树内容扩为：`recipe.json`（或旧名 `session.duck`）+ 源快照 `<ref>.duckdb` + 伴生库与 WAL + `assets/` + `artifacts/`；**关闭会话的磁盘常驻从纯 recipe 变为含源快照拷贝**，直至会话删除——这是 resume 独立性的对价。
- 校准 ADR-0005：L3 资源上限的施加通道与默认值不变；文件连接下 `memory_limit` 事实上覆盖表存储缓存（不再有不可逐出面）。
- 校准 ADR-0027：「每会话一个独立内存 DuckDB 实例」→「每会话一个独立 file-backed DuckDB 实例」；物理隔离、每会话单飞行、各自上限语义不变。
- 校准 ADR-0034：Decision 2「缓存落盘是优化、非真相来源，v1 不做（YAGNI）」的延迟条件已由主形态大文件负载触发，本 ADR 即该款预留的后续决策——伴生库为派生缓存、recipe 仍是真相来源的边界不变；Decision 4 急切重放在水印命中路径豁免，失配路径原样保留。
- 校准 ADR-0035：完整性校验在命中路径后果软化（源消失的阻断/re-link 与源漂移的重建/中止抉择 → 源状态提示）；重放路径语义不变。
- 校准 ADR-0089：per-session 树内容扩容；「复制目录 = 完整会话」从携引用升级为携数据（应用内导入导出入口仍不设）。
- 校准 ADR-0104：按需物化三决策与 Decision 4 的「resume 时物化」语义不动；Decision 4 的急切重放在水印命中路径随 ADR-0034 Decision 4 一并豁免；Considered 末条的重命名否决随 Decision 5 失效。
- wire 面变化：`SessionMetadata.duck_path` → `recipe_path`，前后端同 PR；tray 载荷语义不变（携带路径本身）。
- sandbox 每轮的结果历史镜像仍为内存形态（count/row cap 封顶），本 ADR 不动。
- 设置界面 `memory_limit` 文案随语义表述校准。
- 留实现期：水印摘要算法与加盖挂点、CHECKPOINT 时机、WAL 清理挂点、树内快照子目录布局、双后缀扫描次序、导入导出对话框过滤。
