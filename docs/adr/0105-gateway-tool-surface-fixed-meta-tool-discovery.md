# 网关工具面：外部工具固定元工具发现面取代平铺广告

## Decision

1. **固定三件套取代整表平铺。** 外部 MCP 工具不再逐个进入工具面广告：桥接的 `tools/list` 与内置运行时的 LLM 工具列表中，外部工具的呈现收敛为固定三件套——`mcp_list_servers`（服务器清单 + 当轮连接结果）、`mcp_search_tools`（目录查询 → 工具卡片）、`mcp_invoke`（调用分发）。内置 DuckDB 工具保持直列（数量少且为领域核心）。工具面的广告成本从此与接入服务器数量脱钩：目录再大，面上恒为三件套定义。

2. **句柄身份全链路贯通。** `mcp__<server_slug>__<tool>`（命名与冲突消歧沿用 ADR-0076）从「广告名」转为「句柄」：搜索卡片的 `tool` 字段、`mcp_invoke` 的寻址实参、审批判据（`mcp__` 前缀谓词）、trace 记录四者同一格式，agent 从卡片原样复制、不感知内部拆分。元工具自身用单下划线名（`mcp_list_servers` 等），不占用双下划线命名空间。

3. **搜索卡片即全卡。** `mcp_search_tools` 的每张卡片 = `{tool 句柄, server 显示名, description, inputSchema}` 四字段——搜到即可组装调用，无第二跳。结果上限 top-K = 10，超出提示收窄查询。匹配语义：查询按空白分词，token 间 AND，每个 token 大小写不敏感地子串命中 {服务器显示名, 原生工具名, description} 并集；结果按注册表顺序稳定排序（不打相关度分）；空查询返回全目录（截断前 10）。目录只含当轮连接成功的服务器，启用但连接失败的服务器不留在目录占位。

4. **解析前置，invoke 对强制点不可见。** 网关 dispatch 第一步解析句柄，解析后的身份交给分级审批（ADR-0080）、审计、trace、物化 / 派生归因——各层行为与平铺时代逐位相同。trace 记后端工具调用（句柄 + 参数 + 结果摘要 + 成败），不产生 `mcp_invoke` 条目；句柄解析失败（不命名空间 / 无匹配服务器）作为该次调用的失败结果返回，不产生轨迹条目——与「调用从未到达工具」的既有语义一致。

5. **结果透传。** `mcp_invoke` 原样返回后端 `tools/call` 结果（content 块、`isError` 等逐字段），不包信封、不做归一化投影；工具级错误保持工具结果形态，agent 自纠信号（ADR-0077）不变。网关附加的只有路由失败的可归因错误（点名目标句柄与原因）。

6. **单面同源、轮次边界硬切、空集条件挂载。** 三件套由网关一处装配，内置运行时（进程内）与外部运行时（经桥接）消费同一份面、进入同一分发管线；切换一次完成，无双模式、无配置开关。有效外部 MCP 集为空的轮次不挂三件套——零外部服务器的常态不为其付常驻成本。

## Context

ADR-0076 确立网关聚合 + 平铺广告：每轮 `connect_all` 连接启用服务器，全部工具以 `mcp__<slug>__<tool>` 整表并入工具面。每个工具定义随工具面进入每个 LLM 请求，与该轮是否使用无关——目录达数十上百工具时，对话未开始即占用可观上下文；且上下文压力迫使用户在连接前预筛服务器，未被启用的工具对 agent 不可达，损害工具选用决策。该成本随接入数量线性增长。

## Why

1. **广告成本与目录规模脱钩。** 平铺的 token 成本是每请求线性税；发现面把广告成本压到恒定三件套，「连多少服务器」与「上下文花多少」解耦——被排除的工具重新可达，预筛负担消失。
2. **对 LLM 最不易错的寻址。** 单字段句柄原样复制没有拆分出错的机会；结构化二元组要求正确拆两段，目录短 id 则引入第二套身份且审计不可读。
3. **强制点语义零漂移。** 解析前置使审批 / 审计 / trace / 派生归因继续消费后端工具身份——网关作为唯一强制点（ADR-0076）的承诺在广告形态变更下逐位保持。
4. **调用路径最短。** 卡片即全卡，搜到即可组装调用；两跳式为省未入选卡片的 schema，付出第四工具位与每次调用的额外往返。

## Considered options

- **全功能对齐独立网关产品形态（REST capability 声明、webhook、熔断器、身份传播、操作员面板）**：那是产品面而非模式本体，服务于多租户 / 服务端拓扑；单机桌面无这些服务对象。**否决**——只取发现面模式。
- **四件套（另设 `mcp_list_tools`）/ 二件套（服务器状态并入搜索结果）**：空查询 + server 过滤已覆盖列举职能，独立列举是对同一目录的第二条读取路径；服务器状态并入搜索污染每张卡片。**否决**——三件套。
- **结构化二元组寻址（server + tool 两参数）/ 目录短 id 寻址**：拆两字段增加抄写出错面；短 id 引入 id 与名字间的第二身份系统，resume / 审计不可读。**否决**——单句柄串。
- **两跳式（卡片不带 schema，另设 `mcp_get_tool_schema`）**：每次调用多一跳、多一个工具位与协议步骤，为省几张卡片的 schema 付结构性复杂度。**否决**——卡片即全卡 + top-K 封顶。
- **双模式过渡（配置项切换平铺 / 发现面）/ 平铺永久可选**：工具面是每轮瞬态装配物，无持久迁移负担，双轨纯付组合翻倍的测试矩阵；技能指引、审批判据、trace 语义分叉出两条真相。**否决**——轮次边界硬切。
- **invoke 结果包信封（ok / error 两形态）/ 归一化投影**：信封把工具级错误提升到 invoke 层，破坏 ADR-0077 的自纠信号；归一化对 N 种服务器做有损投影，丢字段责任归网关，且运行时本就读得懂 MCP 原生结果。**否决**——透传。
- **强制点上移到 invoke 层（审批 / trace 记「调用了 mcp_invoke」）/ trace 双记**：审批只见信封即失去分级判据，「允许调用 mcp_invoke 吗」对用户无信息量；双记让审计跨两条记录拼一次逻辑调用。**否决**——解析前置、invoke 不可见。
- **内置运行时保平铺（仅外部运行时切换）**：token 税对内置运行时的 LLM 上下文同样成立；会话内换运行时（ADR-0076）会遭遇面分裂。**否决**——单面同源。
- **TF-IDF 相关度排序 / 整串裸子串匹配**：几十工具规模下打分无查准增益且引入非确定性顺序；整串匹配使多词查询要求连续命中，命中率骤降。**否决**——分词 AND + 稳定排序。
- **空目录恒挂三件套**：零外部服务器是常态形态，恒挂为其付常驻税。**否决**——条件挂载。
- **目录跨轮缓存 / 常驻连接（现在就做）**：当轮目录即弃是最简且隔离最好的形态；规模压力真实出现时按 Consequences 的分界演进。**否决**——留触发条件。

## Consequences

- **校准 ADR-0076**：聚合立场、命名空间句柄身份、网关唯一强制点全部保留；「内置运行时的 LLM 调用直接带聚合工具表」校准为「直列内置工具 + 元工具三件套」，「bridge / 内置运行时 LLM 发 `tools/call` 带命名空间名」校准为经 `mcp_invoke` 句柄寻址。ADR-0076 已加反向指针。
- **跨语言搜索的诚实局限**：子串匹配不做语义翻译，中文查询对英文 description 须 agent 自行翻译查询词——记录为已知局限。
- **发现往返代价**：首次使用某外部工具前置一次搜索（同轮可复用早前结果）；换取的是 token 面恒定。技能提示片段中「直调 `mcp__<slug>__<tool>`」式的指引须改写为搜索 + invoke。
- **规模演进的已知分界**：目录增长至几十上百时，平铺成本已由本决策消除，剩余压力依次出现在连接经济学（每轮串行 `connect_all` 的 spawn 开销——修法为按服务器跨轮复用的常驻连接池，属传输层优化，与运行时无状态 / 每轮装配语义相容）与条目归属（市场 / 插件来源条目的 `source` 轴）；均为加法演进，触发时另立 ADR。
- **CONTEXT.md 校准**：「网关」词条的「装配工具表」措辞改为发现面表述。
- **留实现期**：三件套的 inputSchema 具体形状、搜索实现、句柄解析贯通审批 / trace 的测试钉、桥接与内置两消费方的切换提交、技能提示片段的指引改写。
- **被 ADR-0108 校准**：本 ADR 的「外部工具」指 MCP 运输层；用户注册的 CLI 工具直列进工具面——本 ADR「数量少」的直列依据由此延伸到用户注册工具（数量少、显式注册、稳定存在），三件套维持 MCP 专属。
- **被 ADR-0110 延伸**：元工具家族新增成员 `activate_skill`——同一装配纪律（网关一处装配、两运行时同面、空集条件挂载）；三件套维持 MCP 专属、直列形态不变。
- **被 ADR-0111 延伸**：元工具家族新增成员 `read_skill_file`（激活集非空时挂载）——同一装配纪律；三件套维持 MCP 专属、直列形态不变。
