# 内置技能资产化：文件树随版嵌入、只读整树对齐与本地覆盖

## Decision

1. **定义本体 = 随版文件树，编译期嵌入。** 内置技能的定义本体（`SKILL.md` 与随附 `scripts/`、`references/` 等任意资产）以真实文件树住 app 源码资产目录，编译期整树嵌入二进制；代码侧仅保留 manifest——技能名、CLI 伴随关系（ADR-0120 Decision 7 的可选伴随）与门控元数据。构建对资产树全量声明 rerun-if-changed（含新增文件）。多文件能力就此为一等形态：策展技能可携带脚本、参考文档与非文本资产，物化产物与用户导入技能的目录形态同构。

2. **英文单语。** 内置技能文件本体统一英文，不再维护多语言版本——`SKILL.md` 的消费者是模型，策展 prompt 以英文撰写触发最稳；面板查看的本地化诉求属 app i18n 层职责（暂不实施：英文 description 与 MCP 工具描述的现状一致）。物化 locale 解析、按 locale 渲染、locale 记录随之退役。ADR-0120 Decision 7 的「双语（en-US / zh-CN 随响应 locale）」就此校准。

3. **物化 = 保留子树内的只读缓存，整树对齐。** 内置技能物化到技能库保留子目录（`.system/`），registry 扫描显式并入（通用扫描跳过隐藏目录）。对账以嵌入树的指纹为准——全量文件按排序路径 + 内容哈希，指纹落子树内 marker；一致即跳过，不一致删除子树整树重写。物化文件是 app 缓存而非用户内容：不做编辑检测、不做编辑保留、不做恢复动作，外部编辑在下一次对齐时重置。ADR-0109 Decision 6 对 Decision 2 基线语义的套用就此解除（Decision 2 本体的 CLI 注册项基线语义不动）；技能基线 side table 与逐技能 hash+locale 记录由子树 marker 取代。物化失败按技能名暴露于扫描载荷（面板警示）的既有语义不变，挂到整树写入。

4. **变体通道 = 文件系统复制。** 用户定制内置技能的方式：把 `.system/<name>/` 复制到技能库根（原名或新名），即得可编辑、可删除的本地技能。app 内 create / import / rename 的保留名拒绝（不得撞内置技能名）维持——app 边界拒绝主动制造同名，文件系统层自由。此通道低频且面向高级用户，不设产品化入口；内置技能行保留「打开位置」锚点即足够支撑。

5. **同名时本地技能压制内置。** 技能库根存在与内置技能同名的本地技能目录时：内置技能不并入注册表（数据层始终单份），列表、调用、自动包含全部解析到本地技能；本地技能删除后，下次扫描内置技能恢复生效。语义与 ADR-0109 Decision 7 在 CLI 项上确立的「内置退让、用户先来」同构——机制从「物化 defer」换为「读取压制」（物化永远按对齐发生，退让只发生在并入判定）。本地技能行携带「覆盖内置」徽章：复制之后内置侧的策展演进对该技能不可见，徽章即该信息不对称的常驻提示。

6. **保留面。** 单轴关闭语义不变，禁用轴按技能名生效、与来源无关（覆盖中的本地技能被禁用后，内置侧同样不恢复自动包含——名字承载关停意图）；CLI 伴随门控（伴随注册 ∧ 启用）不变，判定读 manifest 与注册表，与文件形态无关。

## Context

内置技能现行形态是源码硬编码：每个技能的 description 与 body 以双语言字符串字面量住在 `builtin.rs`，物化时按 locale 渲染 frontmatter 写单个 `SKILL.md`，基线 side table 记录 hash + locale 承载「用户编辑保留、策展演进跟随」的对账（ADR-0109 Decision 6）。该形态在两个方向上到达边界：其一，物化管线只写单文件，`scripts/`、`references/` 与非文本资产无法表达——策展技能往复杂形态（教学、脚手架）演进时是结构性缺口；其二，双语言与编辑保留让 baseline 契约同时承载 locale 重渲染、编辑检测、恢复动作三个正交关注。ADR-0120 Decision 7 以「技能单文件、双语、不启用 references 多文件物化」显式推迟了多文件问题。系统未发布、无已编辑的存量物化状态——契约更替无迁移面。

## Why

1. **字符串字面量是内容资产的最差宿主**：markdown 活在续行转义里，无 lint、无可读 diff，编辑高危；scripts 与二进制资产则根本无法宿主。文件树与用户技能库的形态一致，嵌入编译即保住单二进制分发的部署性质。
2. **双语的维护成本是一等公民，收益是查看便利**：物化 locale 解析、按记录 locale 升级、locale 切换不重写——三个机制服务一个「面板查看可读」；而 body 的真实消费者是模型，英文策展 prompt 触发更稳。查看体验的正确归宿是 app i18n 层，不是数据文件。
3. **「可编辑」的合理需求全部另有正解**：策展没写好→改好并随版推送（编辑权等于把策展缺陷变成用户的维护负担，还把技能锁死在旧版）；想要变体→复制；不想要→禁用。编辑保留的真实动机是「物化文件住用户目录、外部编辑器总能改」的所有权防御——只读缓存语义让物化文件回到 app 部署的资产，防御对象消失。
4. **整树对齐把「策展演进」与「用户状态」彻底解耦**：无编辑检测粒度问题（单文件 hash 还是树指纹）、无逐文件保留语义、无恢复动作；指纹一致零成本跳过，不一致删子树整树重写。

## Considered options

- **单文件 `include_str!` 化（仅解耦字符串）**：解决可读性但不支持 scripts/references，首个复杂技能即被迫二次迁移。**否决**——一步到位文件树。
- **维持硬编码现状**：纯 prose 技能阶段可站住，但结构缺口不闭合且大 body 已付可维护性利息。**否决**。
- **维持双语（zh body 可读性）**：消费者是模型；双语维护成本翻倍且 locale 机制常驻。**否决**——英文单语，本地化上收 i18n（暂不实施）。
- **编辑保留延伸到多文件（逐文件基线）**：需定义文件粒度的编辑语义（改 scripts 不改正文算不算编辑），复杂度陡增且服务一个不成立的诉求。**否决**——整树对齐。
- **仅正文保留编辑、scripts 视为可重置资产**：编辑承诺拆两半，语义不再整树自洽。**否决**——整树对齐。
- **同名两行并置显示**：UI 与调用消歧都要发明新规则，常驻复杂度服务极低频状态。**否决**——本地压制。
- **扫描拒绝加载本地同名技能**：否定文件系统复制通道。**否决**——压制接住。
- **「复制为本地技能」产品化入口**：低频高级操作，产品面不划算。**否决**——手动复制 + 打开位置锚点。
- **marker 持久化进 app-config（沿 side table 载体）**：指纹是可重建的观测快照而非用户意图，住子树内即够，无需进用户配置。**否决**——子树 marker。

## Consequences

- **校准 ADR-0109**：Decision 6 的「可编辑并套用 Decision 2 的基线语义」读作「只读 app 缓存、整树对齐」（Decision 2 本体的 CLI 注册项基线语义不动），「进全局技能库」形态化为「物化到保留子树、扫描显式并入」；技能侧对 Decision 7 在 CLI 项上确立的退让语义的同构实现由「物化 defer」机制化为「读取压制」；「留实施期」中的「内置技能正文的 i18n」关闭（英文单语）。
- **校准 ADR-0120**：Decision 7 的「技能单文件、双语（en-US / zh-CN 随响应 locale），不启用 references 多文件物化」读作「技能为文件树、英文单语、支持 scripts/references 多文件」；Considered 的「references/ 多文件渐进披露」否决项就此翻案（复杂技能压力就此真实）；Why 4 所引「用户可编辑 / hash 漂移跟踪」治理随 ADR-0109 校准失效；伴随关系可选化与自动包含判定不变。Decision 3 的 mark 白名单「双份硬编码人工同步」性质不变（前端白名单 + 资产文件两处）。
- **技能注册表数据面**：`builtin_skill_baselines` 字段与 `BuiltinSkillMark` 的 side-table 派生退役；`Acquired::Builtin` 的判定改挂保留子树扫描；保留名集合改读 manifest。
- **CONTEXT.md**：「内置技能」词条校准（只读、英文、保留子树、覆盖语义）。
- **留实施期**：资产目录的路径与命名；指纹算法（排序路径 + 内容哈希 + 版本盐）；保留子树扫描并入顺序与压制实现；覆盖徽章的 catalog 文案；「打开位置」锚点核对；导入通道隐藏目录跳过语义的复用核对；受限读取面对保留子树内附件路径的覆盖核对；物化失败可见性挂点迁移；未发布前提下的旧字段直接删除。
