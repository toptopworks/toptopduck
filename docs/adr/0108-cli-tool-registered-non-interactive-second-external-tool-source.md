# CLI 工具：用户注册的非交互命令工具成为外部工具第二来源

## Decision

1. **外部工具第二来源，统一概念，默认空。**「用户配置的外部工具」成为统一概念，下挂两种运输层：**MCP 服务器**（已有）与 **CLI 工具**（新增）。工具级语义同构——具名工具 + 参数 schema + 分级审批 + 审计 + 轨迹；差异仅在执行运输（网关代 spawn 子进程，而非 MCP 协议会话）。注册 / 启用是机器级、与 MCP 服务器同一启用轴（禁用为绝对权威）；出厂不注册任何项，空注册集是合法状态。

2. **注册数据定义。** 注册项 = `name`（kebab-case、≤64，不得撞内置工具名、`mcp__` 句柄前缀与元工具名，注册时校验）+ `description`（必填，LLM 可见）+ `executable`（PATH 解析或绝对路径）+ argv 模板（占位符字符串数组）+ 参数表（逐项 = `name` / `description` / 传值方式；参数类型 v1 为字符串，唯一复合类型例外见决策 4）+ 可选非秘密 env 映射（字面值，spawn 时与继承 env 合并、注册值覆盖同名继承值）+ 启用状态。探测语义仿适配器探针：注册不因 executable 缺失而阻塞，运行时不可解析返回结构化工具错误（喂自纠循环），条目悬空保留、修复后自动复效。

3. **直接 `argv` spawn，绝不 shell，仅非交互批处理。** 执行走进程级 `argv` 数组，不经任何 shell 解释器：无管道、重定向、glob、变量展开、命令链接；子进程 `stdin` 仅接受声明的参数值（写完即关），无交互。目标工具类 = 非交互批处理（单二进制子命令族、转换脚本、语言解释器）。代码解释器是「参数恰为自由代码」的注册项退化解，非独立机制、不打包解释器。

4. **参数传值三选，逐参数注册时声明。** `argv`（默认，值直接替换进 argv 元素）| `file`（值写入会话工作临时目录的临时文件，占位符收到文件路径；临时文件于调用结束即删，成败皆删）| `stdin`（值写入子进程 stdin 后立即关闭，每次注册至多一个参数声明）。不做按长度自动切换。另设唯一复合类型：`string[]` 变长 argv 参数，整体追加至 argv 尾部，支持「整二进制包装」式注册（一个注册项覆盖一个 CLI 的全部子命令，一个信任决策）。

5. **执行语义。** 工作目录 = 会话工作临时目录（`fs_acl` 读写区，工具产出天然落在 agent 可读区）；无单调用超时，吃轮次墙钟预算，轮级取消映射为进程树终止；stdout 字节帽 + 显式截断标记（超限非致命）；退出码 ≠0 = 结构化工具错误（stderr 同样带帽），喂自纠循环；=0 为成功，结果 = stdout，stderr 非空加标记附于尾部。工具产出文件留在工作临时目录，进工作集走既有通道（探索 / 物化 / 派生源），不新开路径。

6. **工具面直列，单面同源不变。** CLI 工具**直列**进工具面——数量少、显式注册、稳定存在，直列依据与 ADR-0105 内置工具的「数量少」同理；固定发现面三件套为广告成本随目录规模增长的大目录而设，维持 MCP 专属。工具面 = 直列（内置 DuckDB 工具 + 注册 CLI 工具）+ 三件套（外部 MCP 工具）。面由网关一处装配，内置运行时与外部运行时消费同一份——注册工具对两运行时可见，调用一律经网关审批 / 审计 / 轨迹。

7. **审批复用外部工具档，技能引用对称扩展。** 默认逐次确认；「始终允许」升级为按工具的会话级信任（信任键 = 注册名，不进 recipe、resume 归零）；免确认姿态原样覆盖；审批卡片渲染将被执行的完整 argv。不为 CLI 工具立更高档。技能可声明性引用具名 CLI 工具，语义与 MCP 服务器引用逐位相同——不注册、不启用，引用悬空走既有提示路径。

## Context

ADR-0079 把能力边界降为默认技能集语义，扩展路径经技能与外部 MCP 工具打开。但 MCP 出口要求用户实现或获取一个服务器进程——对已持有命令行工具或脚本的用户，能力扩展仍隔一层重步骤。命令行生态存在一类为 agent 设计的单二进制、非交互、面向子命令的工具（文档处理、格式转换、数据清洗、语言解释器），它们不属于 MCP 形态；内置运行时的工具箱仅含 DuckDB 工具与 MCP 工具，此类需求目前只能整体让渡给外部运行时。

## Why

1. **统一概念而非新概念**：CLI 工具与 MCP 工具在网关与审批层完全同构（具名、参数、分级审批、审计、轨迹），差异仅执行运输——一个概念两种运输层，避免词汇分裂与强制逻辑双份。
2. **直列而非发现面**：ADR-0105 内置工具直列的依据是「数量少且为领域核心」；注册 CLI 工具同样数量少且稳定存在，落在「数量少」依据的同侧；发现面解决的是大目录下广告成本随规模线性增长的问题，对 CLI 工具不成立，而目录当轮即弃反成高频主力工具的每轮发现税。
3. **直接 argv spawn 而非 shell**：不经 shell 解释器，注入面与引号歧义同时消失；非交互批处理恰好覆盖目标生态，同时进程生命周期（墙钟、取消、树终止）完全由 app 可控。
4. **显式声明而非启发式**：按长度自动切换传值会使同一参数有时是值有时是路径，`-c {code}` 类命令会把文件路径当代码执行；声明把语义在注册时钉死。
5. **默认空**：默认能力边界（以 SQL/DuckDB 原生为界）是产品身份陈述；默认装机零新增执行面；注册表单是该工具的唯一配置面，用户无终端步骤。
6. **审批复用、不立新档**：「CLI 比 MCP 更危险」是能力类判断——启用的 MCP 服务器同样可做任意文件 / 网络 / 子进程，运输层不是分档依据（ADR-0079 已否决能力类审计）。

## Considered options

- **通用 shell 执行工具（agent 拼任意命令）**：向外部运行时收敛、模糊双运行时产品边界；无「按工具」信任粒度，审批摩擦与能力边界同时失守。**否决**。
- **内置默认代码执行能力（出厂带代码解释器）**：须打包运行时（发行重量级决策）或依赖系统解释器（环境碎片化）；且默认承认 SQL 不够，是产品定位级变更。**否决**——默认空，解释器为注册项退化解。
- **进固定发现面（与 MCP 同走三件套）**：发现机制是 MCP 形状（服务器 / 连接结果 / `mcp__` 句柄词汇），CLI 无 server，强入则拉伸词汇、三件套命名随之漂移。**否决**——直列。
- **为 CLI 立更高审批档（严于 MCP，如禁止会话信任）**：能力类审计，正是 ADR-0079 否决的路径。**否决**。
- **按长度自动切换传值**：非确定性，见 Why 4。**否决**。
- **挂技能下（技能第三组件）**：技能是会话级挂载物，工具配置是机器级，混合造成「卸载技能是否删除工具配置」的归属撕扯；MCP 引用当年也未挂技能下。**否决**。
- **秘密 env 进 v1（CLI 注册项加 keychain 通道）**：当前动机场景无秘密需求；需要密钥的集成已有 MCP 出口；范围纪律，将来为加法演进。**否决**——v1 仅非秘密 env。
- **支持交互工具与 shell 语法**：进程生命周期与审批语义失控；非交互批处理已覆盖目标生态。**否决**——进 v1 排除清单。
- **自动安装缺失的 executable**：app 不下载并执行第三方代码；探测 + 结构化错误 + 自动复效是诚实形态。**否决**。
- **对外部运行时隐藏注册工具（工具面异源）**：违 ADR-0105 单面同源；会话内换运行时遭遇面分裂。**否决**——两运行时同源可见。

## Consequences

- **CONTEXT.md 校准**：首段工具箱与扩展路径、联网免责句、「工具」「网关」「技能」「派生源」词条修订，新增「CLI 工具」词条。
- **延伸 ADR-0079 扩展路径**：技能、MCP 工具、CLI 工具三成员；边界语义由「每技能」校准为每技能 / 每工具；默认行为不变（默认空）。
- **与 ADR-0107 无冲突并存**：0107 否决 yoagent 内置工具，因其绕网关；CLI 工具经网关强制路由，是同一原则的相反实现，该否决不需校准。
- **外部运行时同源可见**：注册工具出现在桥接工具面，外部 agent 的调用同样过审批 / 审计 / 轨迹；其原生工具仍归第三方，不变。
- **工具进程自身行为归第三方**：网络行为（如自带的更新检查）、常驻子进程（如命名管道会话）属工具自身；app 可控面限于所 spawn 的调用与其进程树终止。工具侧的配置需求（如禁用更新检查）经注册项 env 声明。
- **产物出路为开放话题**：CLI 工具产出的文件留在会话工作临时目录（会话目录树内），非 Dataset、不进工作集；「产物如何呈现 / 导出给用户」另立话题，v1 轨迹展示工具输出。
- **留实施期**：注册表单与探测 UX、三传值方式的 spawn 实现、Windows 进程树终止（job object）、stdout 字节帽与既有工具结果帽值对齐、桥接 `tools/list` 纳入注册项、技能引用悬空提示的测试钉；预设注册表（一键注册）为后续 UX。
- **被 ADR-0109 校准**：四处——本 ADR「出厂不注册任何项」读作「出厂无已注册项；app 随版的内置定义经本地安装检测自动注册」（预设注册表的开放话题由 ADR-0109 满足，形态为内置注册项 + 检测自动注册，非一键注册）；Decision 3 的代码解释器退化解晋升为策展内置项（不打包解释器不变）；Decision 2 注册名防撞校验追加「不得撞内置 CLI 注册项名」；Decision 7 审批卡增加 `file` 传值内容按需查看（默认仍渲染完整 argv）。本 ADR 的「注册项」措辞读作用户 CLI 注册项。
- **被 ADR-0109 延伸**：本 ADR 未决注册表载体；ADR-0109 定为 app-config（与 MCP 注册表同居），一切写入经后端读改写命令，后端发起写集中于启动窗口（重扫路径经 IPC 返回即同步）。
