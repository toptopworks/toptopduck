# 记忆层：工作区与用户双层、文件为准存储与宿主门控索引注入

## Decision

1. **记忆分两层：工作区资产层与用户层。** 工作区层随工作区存在并可随其共享（是否纳入版本控制由用户自定），承载项目约定与该工作区的偏好；用户层落应用数据目录 `<app_data>/memory/`，承载跨工作区的身份与偏好，是本机私密资产、永不进入可共享面。两层格式同构（同一平铺 frontmatter 与文件命名，用户层条目 type=user），未来迁移零成本。

2. **存储为文件为准、索引为派生投影（两层同律）。** 工作区层落 `<工作区>/.toptopduck/memory/`（沿数据集状态目录先例）：一事实一文件 `<type>-<slug>.md`，平铺 frontmatter（name、description、type、origin_session、saved_at 绝对日期、source），四分类 user/feedback/project/reference。`MEMORY.md` 为派生索引，一行一事实（标题、文件、hook），每次读取从文件重算、漂移即回写校正——文件恒赢，索引永不反向覆盖文件。

3. **内置引擎每轮注入索引块，只带标题与 hook（两层的共同注入面）。** 两层索引在系统提示拼接为同一记忆块，块内用户层在前、工作区层在后（项目语境覆盖用户通则）；注入组装序为基础提示→技能索引→记忆索引→语言指令→数据上下文。不注入正文（内置引擎无文件读取工具，正文注入是无消费方的体积），不带文件链接（模型在此通道打不开文件，链接是死噪声）。存储文本在注入侧不可信：布局控制字符折叠为空格、按字符边界截断——与技能索引描述同一注入不信任姿势，手改文件无法伪造行或伪标题。记忆集为空时不渲染块；读取失败恒为空集，绝不阻塞轮次。

4. **外部 agent 零注入，两层分界不同。** 外部 CLI agent 通道不注入任何记忆内容。工作区层正文本在工作区内、任何 agent 可用自身文件工具原生读取，缺的只是「知道它存在」的可见性——可见性注入面（受管块或网关工具）连同其主权规则属后续独立裁决，首版只钉零注入边界；用户层是私密资产，与可共享的受管块通道无干净叠加方式，不进入外部可见性面。

5. **宿主唯一写者，上限拒绝不截断（两层同律）。** 首版无前台直写与自动提取（后续批次另议）；用户层首版为纯手写通道，不做自动提取的归属路由（有真实数据后再裁）。首条记忆诞生前零目录足迹。索引双帽（行数与渲染字节）超限时拒绝新条目并告警——不静默截断、不头部截断丢旧；每条截断路径按字符边界行走，汉字不从中点劈开。

6. **开关落宿主 registry 记录，默认开。** `memory_enabled` 是宿主侧资产属性（每台机器各自决定注入），不落可共享的工作区目录；默认开，仅显式关闭时序列化（additive 字段，双向升级中立）；关闭=停注入+停面板列表，读路径本身不受影响。写路径的自动提取开关独立且默认关，与本开关分离。

7. **提取模型与运行时解耦，独立可选设置加兜底链。** 自动提取的模型调用走独立提取模型设置（全局，与壳接入档案同层、同配置形态）；未配置提取模型时兜底壳活跃接入档案；两者皆无则提取静默跳过——仅停写路径，注入、面板与手写通道不受影响。提取是壳侧任务：消费会话记录、产出记忆条目，与轮次由哪个引擎驱动无逻辑依赖。

## Context

跨会话重复交代偏好与项目背景的成本：身份、习惯、项目约定在每次新会话里重新陈述——其中身份与偏好是跨工作区事实（工作区层装不下），项目约定是工作区局部事实（全局层会混入无关工作区）。工作区绑定与 registry 已就位，系统提示组装点已承载技能索引与数据上下文的常驻注入；数据集已在 `.toptopduck/` 下建立工作区状态目录先例。用户混用多个 agent（内置引擎与外部 CLI）的场景真实存在——同一工作区内，各 agent 各自的原生记忆互不可见，立过的规矩不跨 agent 生效。

## Why

1. **两层对应两类事实的归属**：跨工作区的身份偏好跟着人走（应用数据目录），项目约定跟着目录走（工作区内）；单层必然让项目约定混入无关工作区，或把身份偏好困在单工作区。
2. **同构格式使两层零迁移**：一套解析、一套面板、一套注入拼接承载两层，用户层只是存储位置与条目分类不同的同款公民。
3. **文件为准使手写与漂移都安全**：面板明示「任意编辑器可写」，手写文件是一等公民写入路径；git 可 diff、可部分采纳；派生索引的漂移修复方向机械确定（重算即愈），永不出现两份真相。
4. **索引注入是体积与价值的平衡点**：标题加 hook 承载「背景上下文」职能所需的最小面；正文体积不可控，且内置引擎无文件读取工具可展开消费。
5. **注入侧不信任存储文本与技能索引同姿势**：记忆文件是可手改的持久输入，防伪造行与伪标题的钳制必须在注入面而非写入面把关——写入面无法拦截手改。
6. **默认开让被动收益可见**：读路径的价值在不重述，默认关会让功能死在设置里；风险面集中在写路径（自动提取的成本与误报），读写开关分离使默认值各对齐各自的风险面。
7. **提取模型解耦对齐成本与任务量级**：提取是机械任务，挂在会话主模型价上等于以最贵单价跑最便宜的任务；独立可选设置让成本可控（配小模型跑提取），兜底链让零配置行为与绑定形态一致——未配置提取模型者无感知差异。
8. **零足迹保持无记忆面的干净**：不为「可能有记忆」预建任何目录。

## Considered options

- **单一全局记忆库（不分层）**：跨工作区事实与工作区局部事实混装，要么项目约定进入全部工作区、要么身份偏好只困在单工作区。**否决**——两层（Decision 1）。

- **用户层走外部 agent 可见性通道（与工作区层同款受管块）**：受管块是随工作区共享的资产，用户记忆是本机私密资产，两者叠加无干净主权分界。**否决**——用户层不进入外部可见性面（Decision 4）。

- **外部 agent 逐适配器注入（CLI 标志或配置键）**：注入通道数乘适配器数的维护面，且与各 agent 自有记忆系统叠加产生双重指令。**否决**——首版零注入（Decision 4）。

- **AGENTS.md 受管块作外部可见性注入（工作区层）**：marker 主权分界（壳主权块内、用户主权块外永不触碰）是全新治理面；增量仅是可见性，正文本可原生读取。**否决**——后续独立裁决（Decision 4）。

- **外部 agent 前台直写记忆**：多写者使 origin_session 与时间戳失去宿主这个唯一可信来源，冲突合并面随之而来。**否决**——宿主唯一写者（Decision 5）。

- **功能整体默认关**：读写共用一个开关会把读路径的被动收益一并埋掉；风险只在写路径。**否决**——读写分离默认（Decision 6）。

- **超限静默截断**：无论丢头部还是丢尾部，都是用户不知情的记忆丢失。**否决**——拒绝加告警（Decision 5）。

- **索引独立存储（非派生）**：面板邀请手写文件，两份真相的漂移必然发生且无机械修复方向。**否决**——索引恒为投影（Decision 2）。

- **提取模型绑会话引擎（无独立设置）**：主模型价跑机械任务，且外部 agent 会话提取落地时绑定必拆。**否决**——独立提取模型加兜底链（Decision 7）。

## Consequences

- 常驻注入面扩一块：默认开姿势下每轮系统提示携带两层拼接的记忆索引块；两层皆空的工作区零字节开销。

- 注入块措辞与行形态为冻结模板：任何措辞变更属规格变更，不是文案调整。

- 实施按层切片：工作区层读路径与面板先行；每轮后自动提取（消费既有写原语，独立开关默认关）、用户层（手写通道+面板区+注入拼接）随后；索引蒸馏回收最后——各自落地时另行校准或扩决策。

- 外部 agent 可见性注入（受管块或网关工具）落地前须重开决策，主权规则随落地一并定形。

- 面板首版为只读列表（含在系统文件管理器中定位记忆文件）：编辑走任意外部编辑器，壳内编辑器后议。
