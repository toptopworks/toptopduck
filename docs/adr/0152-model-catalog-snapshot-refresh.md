# 模型目录：构建期快照打包与运行时惰性刷新

## Decision

模型目录治理为**三层数据面 + 一条惰性刷新管线**。数据面三层：磁盘缓存（应用数据目录，紧凑 schema gzip）、构建期快照（发版流程生成步骤拉取 models.dev、裁剪为紧凑 schema——唯一模型 id 映射显示名 / context 窗口 / 输出上限 / effort 档值列表，gzip 随二进制打包；repo 不落手更数据文件）、既有家族前缀表（保留，职责收缩为目录未收录的别名与自定义部署 id 的家族兜底，更新频率降为全新家族才补行）。查表优先级链恒为缓存精确 id、快照精确 id、前缀表、空心态/兜底；占用环分母与轮次输出上限两查表点改走全链，输出上限的 min 钳制公式不变，仅数据来源切换；新增 effort 档查询入口供姿势选择面消费。刷新为惰性静默：磁盘缓存距上次成功拉取超过 24 小时后，下一次目录消费（内置 turn 起点；姿势菜单加入在后继票）触发一次后台补拉，当轮以旧值作答不阻塞；CLI 通道的占用盖章是纯链读、永不触发，零档案与纯 CLI 会话全程零出网。拉取失败、离线、解析失败一律静默沿用旧缓存（无旧缓存用快照），不新增失败 UI 与用户可见状态；重试节奏即同一 TTL，不设退避阶梯。缓存与快照同 schema：上游改版只影响新拉取的解析，serde 字段只增不删使旧缓存永不因 schema 演进损坏，损坏缓存静默跳过永不删除。出网仅此一个公开无鉴权端点，走共享阻塞 egress client（重钉关停）。

## Context

ADR-0130 Decision 4 立法占用分母取自静态模型目录（models.dev 值的内置前缀表），其 Considered 同时预留「目录刷新——出现真实诉求另议」：新模型最长要等一个 release 才进表，社区模型迭代快于发版节奏，该假设诉求已被触发（同一源头的输出上限低容表同构受限）。前缀表是家族粒度：别名（如部署 id）靠家族兜底可覆盖，但新家族 / 新代际在表外即空心终态。推理强度档（effort 离散值）此前无任何目录来源，wire 层高档写死，需要一手目录底座。上游 models.dev 提供公开无鉴权的全量 JSON dump（api.json，万级条目，绝大多数条目带 context 窗口与输出上限，约八成带推理元数据），是两表既有共同出处，天然是唯一刷新源。

## Why

1. **新模型即时可用，零用户动作**：快照让每个发版自带当期全量目录，惰性刷新让发版间隔内的新模型在首次消费后 24 小时内到位——两条腿都不需要用户触发或感知，ADR-0130 否决的「刷新按钮」所担心的拉取+存储+失败态复杂度由静默管线吸收。
2. **精确 id 优先于家族前缀**：同 id 跨 provider 冲突按确定性规则解决——canonical 行（`canonical_model_id` 指回自家 provider，即实验室一手行）权威优先，其余按 provider 键排序首见胜出；实验室行权威避免了字母序在前的转售商（数字前缀 id 排最前）以陈旧限额覆盖现行模型（上游约 2.6% 的 id 存在此冲突，陈旧 sub-cap 输出上限会复现输出上限被过期值压低的既有截断缺陷形）。快照与运行时刷新按同一确定性裁剪规则产出，同一上游字节恒得同一目录——可重现、可审计。
3. **零档案/纯 CLI 零出网是结构保证而非门控**：触发点唯一落在内置 turn 起点（存在 provider 档案才会到达），CLI 盖章路径是纯读——不需要「是否有档案」的运行时判断，出网面天然收敛。
4. **静默是诚实降级不是吞错**：每一层失败都有下一层接住（旧缓存、快照、前缀表、空心态），用户可见行为与失败前一致；唯一响亮的失败点是发版流程的生成步骤（快照拉不到即构建失败），把可观测性放在最能使力处。
5. **同 schema 防演进损坏**：缓存落的是自家紧凑格式而非上游原文，上游 schema 改版只影响下一次拉取的裁剪；旧缓存永远按自家向后兼容规则解析。

## Considered options

- **用户触发刷新按钮（ADR-0130 Considered 原案）**：为假设诉求引入拉取+存储+优先级合并+失败态 UI。**否决**——假设诉求已真实化，且静默管线无需 UI 面。
- **常驻巡检 / miss 补拉 / 退避（准实时网关形机制）**：本应用不是网关，不需要准实时目录；miss 即触发还会让任意查表 miss 都成为出网点。**否决**。
- **构建期 build.rs 直接拉取**：每次本地构建触网（或离线即败），开发体验与离线构建不可接受。**否决**——生成步骤独立于 cargo 构建，快照缺席时代码面嵌入空快照照常构建。
- **repo 内提交手更数据文件**：三平台构建共享一份提交数据，但回到手更节奏（发版前的最后一次手动更新仍会落后于当日新模型），且 60KB 二进制数据进 git 违反仓库无数据文件现状。**否决**。
- **缓存存上游原文、读时裁剪**：上游改版即刻破坏旧缓存解析，违背「旧缓存永不因 schema 演进损坏」。**否决**——落盘即裁剪后的自家格式。
- **删除家族前缀表（目录全覆盖后冗余）**：别名与自定义部署 id 不在目录内，家族兜底仍是唯一解；前缀表职责收缩而非退役。**否决**。

## Consequences

- 发版流程新增生成步骤且为硬门禁：models.dev 不可达即 release 构建失败（快照缺席意味着整版目录停滞一个 release 周期，响亮失败优于静默空快照）。
- 首个内置 turn 可能触发一次后台拉取（首次使用或缓存过期后），此为该管线唯一的计划内出网；请求无鉴权、不携带任何用户数据。
- 失败后的下一次尝试最早在 24 小时后（同 TTL 节奏，无退避）：长运行会话离线一天内的目录停在旧值，接受。
- 紧凑 schema 只增不删字段是缓存兼容的硬约束：删改字段必须同时接受旧缓存作废（静默回退快照，损失为过期数据而非故障）。
- effort 档查询入口本ADR只建面不接线：姿势菜单的消费（一手列表拉取与元数据展示）在后继票；toggle-only / budget-only 行不带离散档，强度面 v1 只接 effort 离散档。
- 前缀表更新语义变化：新家族才补行，不再逐发版追新模型行——表内容 stale 不再是缺陷，目录层负责新鲜度。
