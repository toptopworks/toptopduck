# shell 形态:对话流 + 持久工作集面板

## Decision

thread rail 演进为**连续对话流**：轮次卡片 = 提问 + 可折叠执行轨迹 + 终局答复 + 结果表内联预览卡片；源 / 技能生命周期事件按时序插条（非卡片、标记条）。同时**右侧工作区默认折叠**：数据集总览 / 结果表（ADR-0057）/ Schema / 可视化（ADR-0016/0033）随时可手动展开；冷启动（app / 会话开始）为折叠态、不记忆上次展开状态，**会话内首个 `result_N` 晋升自动展开一次**（带该 Dataset），其后纯手动——展开 / 折叠为会话内临时态。工作区折叠时 **rail 升主变宽**占满释放空间（保最小宽），展开时右侧分栏；结果卡片与工作区面板是同一 Dataset 的双视图（选中联动）。**输入区（QuestionBar）收进 rail 内**：按钮行最左 **「+」按钮**打开**会话上下文面板**，三分区——**添加文件**（源载入，多选）、**技能多选**（会话级挂/卸）、**MCP 工具多选**（用户配置的服务器按会话启用，服务器粒度）；无技能且无 MCP 时「+」退化为纯添加文件按钮。**授权模式（逐次确认 / 免确认）与运行时选择**为按钮行独立入口——技能 / MCP / 文件是同类「会话上下文添加」，授权模式与运行时是「执行姿态开关」；皆是会话级装配配置（按轮注入，ADR-0076），对话按钮行即每轮发起处。**审批确认走流内审批卡片**：命中逐次确认的外部工具调用以 pending 态条目出现在当前轮次轨迹中（工具名 + 操作类型 + 参数摘要 + 允许一次 / 始终允许 / 拒绝三按钮），应答后原地转 resolved 态收进折叠轨迹；网关挂起仅阻断该轮次，不阻断其余会话。

## Context

ADR-0045 定 rail/workspace 分离并显式否决纯内联对话流——分析轮次产出几十列宽的 `result_N` + Vega-Lite 大图，内联 3-5 轮即不可导航；ADR-0060 进一步定 Chat 风格外壳（左会话栏，「Chat 外壳 + 工作台内核」）。agent 化（ADR-0076）后 thread 内容形态变化：多步轨迹、生命周期事件、富产出——0045 的否决理由（宽表大图不可内联）依然成立，但 rail 渲染形态需吸收对话流卡片化。

## Why

1. **对话流是 agent 轮次的原生渲染**：提问 + 轨迹 + 答复 + 结果卡片自然成流；ADR-0045 否决的是「宽表大图全内联」，不是「卡片化流」——结果卡片承载内联预览（窗口化采样，ADR-0026），完整宽表 / 大图由工作区面板持久承载，领域硬约束与流式体验两全。
2. **工作区面板不可退役**：`result_N` 稳定身份（ADR-0037）、active dataset 指针、跨轮 SQL 引用皆需持久面；大表大图完整渲染（ADR-0057 无虚拟化）需稳定容器。
3. **装配入口归对话按钮行、异质分组**：技能 / MCP / 文件是同类「会话上下文添加」（皆按轮注入，ADR-0076），共一个「+」面板；授权模式与运行时选择是「执行姿态开关」，与上下文添加异质，独立入口。「下一轮怎么跑」是每次发起前的操作姿态，入口放发起处（QuestionBar 按钮行）而非会话头部（身份区）。
4. **审批走流内而非模态**：三栏多会话 shell（ADR-0060）下窗口模态会冻住无关会话，而网关挂起（ADR-0080）的语义边界是轮次而非 app；pending 审批本就是轨迹条目的一态，流内形态让决策时刻与轨迹记录共用一条渲染路径；外部运行时单轮多次命中确认时，逐次模态不可用。
5. **工作区默认折叠 + rail 升主**：对话为主面，常驻展开的工作区挤压 rail；默认折叠把空间还给对话，会话内首个结果晋升自动展开一次给「全貌在这里」的指引，其后不抢焦点。

## Considered options

- **纯对话流、无持久面板（全内联）**：宽表大图撑爆流（ADR-0045 Why#2 领域硬约束仍在）；`result_N` 跨轮引用失持久锚。**否决**。
- **守原分析 shell（提问框 + 轮次列表、不卡片化）**：多步轨迹与生命周期事件无天然渲染载体，形态与 agent 轮次结构相悖。**否决**。
- **双模式可切换**：渲染 / 状态 / i18n（ADR-0052）双轨，测试面翻倍。**否决**。
- **审批走窗口模态**：多会话 shell 下冻住无关会话、新工具集首轮连续打断、决策时刻与轨迹记录劈成两处。**否决**——流内卡片 + 未应答徽标染色承载强制可见性。
- **三个选择器放会话头部**：头部是会话身份区，装配配置是逐轮操作姿态，入口远离发起点。**否决**——对话按钮行。
- **技能 / MCP / 文件拆三个独立按钮行入口**：槽位爆炸，且三者同为会话上下文添加。**否决**——一个「+」面板。
- **「+」面板做只读快照、选择全在设置页**：会话级挂/卸是高频装配动作，埋进设置页使操作远离动作。**否决**——面板内多选。
- **MCP 启用到工具粒度**：工具级勾选面爆炸，调用风险已有逐次审批治理（ADR-0080）；服务器粒度足够。**否决（v1）**——留工具粒度出口。
- **工作区常驻展开（ADR-0045 原形态）**：对话为主面后 rail 被持续挤压，宽表大图低频却常驻占位。**否决**——演进为默认折叠 + 晋升自动展开一次。
- **每次结果晋升都自动展开**：抢焦点破阅读流，与默认折叠姿态矛盾。**否决**。
- **工作区折叠时 rail 保持固定宽**：窗口大面积留白，窄列容不下三选择器。**否决**——rail 升主变宽。

## Consequences

- **部分取代 ADR-0045**：rail 形态演进为对话流轮次卡片；rail/workspace 分离架构与「宽表大图不内联」原则保留（内联预览仅承载窗口化采样）。
- **部分取代 ADR-0047**：rail 视觉语言按对话流重写（卡片结构、轨迹折叠态、生命周期事件标记条）。
- **延伸 ADR-0060/0073**：三栏 shell 结构与 session-header（会话身份区）不变；运行时 / 技能 / 授权模式三个选择器归 rail composer 按钮行。
- **推翻 ADR-0054 的 rail 固定宽前提（新 shell 下）**：工作区折叠时 rail 升主变宽；最小宽 + Tauri `minWidth` 兜底、rail 可折叠与窗口尺寸策略保留。
- **QuestionBar 跨度再演进**：从「跨 rail + workspace」（ADR-0062 R1）到 rail 内——工作区默认折叠后全宽跨度失去前提。
- **源载入入口归并**：添加文件入口收进「+」面板（拖放快捷途径保留），原独立加源入口退役；ingest 管线与源生命周期事件（ADR-0040）不变。
- **挂载 / 启用态呈现**：「+」按钮 badge（技能 + MCP 计数）+ 生命周期事件条（ADR-0078）共承，输入区不加 staged chip 行。
- **延伸 ADR-0026**：结果卡片内联预览复用前 3 行窗口化采样语义。
- **CONTEXT.md 不动**：shell 形态是呈现层，不引入领域术语。
- **未决（视觉打磨期）**：卡片视觉规格、轨迹折叠态交互细节、审批卡片在窄 rail 下的参数展开规格、composer 按钮行三选择器与授权模式警告色的视觉规格、工作区自动展开一次的动效。
