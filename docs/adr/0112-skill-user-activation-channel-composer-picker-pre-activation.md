# 技能激活用户信道：输入框触发式选择与提交时物化

## Decision

1. **用户激活信道收敛为输入框触发式选择，挂载列表回归纯信任闸门。** 两个触发字符、同一选择组件、两种呈现模式：`/` 打开**全局面板**（分组呈现，组头「技能」+ 列表），`$` 打开**技能直达面板**（无组头平铺）。挂载列表行尾的激活动作撤除——激活入口唯一化；行内激活徽章保留（状态呈现，非入口）。分组架构承载未来的可选项类型（如子智能体）：第二组落地时自然加入 `/` 面板，`$` 永远只列技能；不预建空组。

2. **选中 = 挂载 + 激活复合意图。** 选中一个技能同时表达挂载意图（若未在）与激活意图；挂载列表勾选仍是挂载单一权威，两处同源同步。级联：取消挂载意图或卸载时，该技能名下的预激活意图一并摘除（「卸载是激活唯一出口」的意图版）——物化层永不命中「未挂载而激活」拒绝。冗余挂载拒绝照旧静默吸收（自动挂载内置技能撞车场景）。

3. **预激活是 composer 持有的内存态意图，非会话状态。** 会话不存在前零状态突变。选中恒落 chip——chip 即「自上次提交以来用户表达过的意图」，可移除；选中行为不查物化态（挂载 / 激活查询缓存是显示性数据，不参与控制流），物化层幂等吸收一切（需挂载则挂载、需激活则激活、都齐则空操作）。冷启动 chip 与待挂载名单同屋檐（shell 内存态）；会话内 chip 随会话视图存续，切换 / 关闭即弃——未提交的意图不跨会话泄漏。

4. **物化时机唯一：提交时。** 冷启动链：建会话 → 起步姿势写入 → 挂载序列 → 激活序列 → 首问；会话内：提交先跑挂载 + 激活序列、再发问——激活在轮装配前落盘，首问即注入正文。thread 时间线如实呈现 Mount → Activate → 首问。提交在轮中本就禁用，与技能变更的轮中拒绝门天然无重叠。

5. **交互契约：行首触发、输入即过滤、单选即关。** 触发字符在行首敲下时开面板（空输入是其特例），行中字符不触发；触发后的输入即过滤查询（名称或 `description` 子串、大小写不敏感，与挂载列表搜索一致）；↑↓ 移动高亮（钳位不环绕）、Enter 选中、Esc 关闭；面板开时 Enter 是选中而非提交，Esc 后触发字符与查询保留为普通文本；失焦关闭面板，重新获焦不自动重开。单选即关面板，多次触发续选。行承载名称、`description`、来源与激活态（纯显示）；行的视觉形态与面板锚定留实施期。

6. **记账走既有事件，无新 IPC、无格式变更。** 物化复用 `mount_skill` / `activate_skill`（用户 actor 落 `Activate` 事件）；recipe format_version 不动。

## Context

用户激活信道此前形态：会话内挂载列表行尾两态动作（激活动作 + 激活徽章），冷启动（会话未建）无任何激活动作——两种模式的激活交互不对称，且冷启动用户「起步就要用某技能」的意图无处表达，只能等会话建立后补激活。输入框触发式选择（敲触发字符浮出过滤面板、键盘选中）在同类产品中已是习得惯例。

## Why

1. **一个域概念一个交互**：激活入口唯一化后，冷启动与会话内不再有两套手势；挂载列表回归纯信任闸门（勾选管理可见性），激活回到输入流里表达——它本是任务级意图。
2. **预激活弥合「会话未建」的时点缺口**：意图先行、提交物化，冷启动链与既有待挂载名单的物化模式同构，零后端改动。
3. **提交单时机**：激活影响轮装配（正文注入），物化钉在发问前是自然同步点；提交的轮中禁用门与后端技能变更的轮中拒绝门无重叠。
4. **选中恒一态**：分期不查物化态，查询缓存的滞后不劫持控制流；幂等物化吸收一切态组合。
5. **双触发字符**：肌肉记忆兼容两类既有惯例；`/` 与 `$` 今日同源（仅技能一组），作用域分化留给第二个真实组——不预建空组、不重训。

## Considered options

- **保留行尾激活动作、冷启动另补一个入口**：两套激活交互并存，用户在两模式间换手。**否决**——入口唯一化。
- **双触发字符作为同一清单的别名**：两字符承担同一语义，作用域无分化。**否决**——`/`=全部、`$`=技能直达。
- **`/` 面板今日预留空组（为不存在的类型占位）**：第二组未落地时预建分组是空结构噪音。**否决**——分组架构就位、空组不建。
- **选中仅写激活意图、挂载留物化时差集补挂**：破坏挂载单一权威，复杂度后移到物化时点。**否决**——复合意图一步到位。
- **`create_session` 参数化初始挂载 / 激活集**：改 IPC 契约，且与自动挂载的静默播种语义纠缠。**否决**——复用既有命令逐个物化。
- **app 级「默认激活集」跨会话持久**：激活是任务级意图非偏好，持久化会把上次激活腐蚀进无关会话。**否决**——预激活随会话 / 视图丢弃。
- **会话内选中即刻物化（激活双时机）**：与冷启动的提交时物化语义分裂。**否决**——提交单时机。
- **已激活技能选中静默无操作**：选中行为分叉即以物化态做控制流。**否决**——选中恒一态。
- **多选面板常开（选中后清查询续选）**：单次会话的续选以单选惯例为简。**否决**——单选即关、多次触发续选。
- **chip 承载去激活（会话内移除已落盘激活）**：绕过「卸载是激活唯一出口」。**否决**——chip × 只撤意图。
- **仅名称过滤（不匹配 `description`）**：匹配口径简单，但凭描述存活的行读不出留存理由。**否决**——扩展为名称或 `description` 子串，与挂载列表搜索同口径。
- **未匹配行变暗不过滤**：查询失去收窄力，列表恒全量渲染。**否决**——保留过滤。

## Consequences

- **校准 ADR-0110**：Decision 4 用户信道由「挂载列表两态」改写为「输入框触发式选择（本 ADR）」；其留实施期清单中的「挂载列表两态 affordance」项由本 ADR 收编。
- **CONTEXT.md 校准**：「技能激活」词条补用户信道（触发式选择、预激活、提交时物化）。
- **既有实现收敛**：会话内挂载列表行尾激活动作撤除；激活徽章保留。
- **零后端改动**：复用 `mount_skill` / `activate_skill`；无新事件变体、format_version 维持。
- **留实施期**：行的视觉形态（图标 / 对齐 / 命中高亮）、面板宽度与锚定、动画、DESIGN.md token 逐项自审。
