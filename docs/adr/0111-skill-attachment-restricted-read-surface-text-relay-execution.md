# 技能附带文件：受限读面与执行文本中继

## Decision

1. **附带文件经网关元工具 `read_skill_file(name, path)` 受限可读，app 代读。** 渐进披露第三层落地：激活技能的目录树内文件（`references/`、`assets/`、`scripts/`、`SKILL.md` 自身——无特权区）按需可读。信道唯一：网关一处装配、内置进程内路由、外部经桥接消费同一份面（与 `activate_skill` 同纪律）；激活集非空的轮次才挂（空集条件挂载同构）。app 代读、agent 不见任何绝对路径。

2. **收口三件套界定可达边界。** ①锚点 = 注册表条目根的 canonicalize 结果（link 导入指向的外部目录即技能本体）；②请求路径词法拒绝：含 `..` 组件、绝对路径、Windows 盘符 / UNC 形态即结构化错误；③canonicalize 后须组件级落于锚点之下且为 regular file——树内 symlink 外指着跟随到真实目标后判出界拒读。可达边界恰等于「用户导入时看到的那个目录树的真实文件」。

3. **门控 = 激活集。** 仅激活技能的文件可读——读资格与正文注入同门（挂载而未激活者无读资格）。卸载级联：激活集收缩则后续轮不可读，收缩到空则工具从两面摘除。轮中激活不与当轮装配竞争：mid-turn 经 `activate_skill` 新激活的技能，其文件下一轮起可读。

4. **发现走正文，自纠三态。** 文件名只能来自激活正文的点名；工具 description 不枚举文件、`activate_skill` 不携带目录结构提示。失败各带自纠信号：`name` 未挂载 → 把全部可发现技能名列在错误内容中（镜像 `activate_skill` 查无此名的错误形状）；`name` 挂载未激活 → 指路先 `activate_skill`；`path` 不存在 / 出界 / 是目录 → 列该技能可读文件清单。清单 = 逐文件过收口规则的真实可读集（外指 symlink 不出现；二进制与超帽文件进清单、读时才分类拒绝）；清单有条目数帽 + 截断诚实标记。

5. **免审批。** 读取物与正文同级风险类（提示注入面——恶意技能文本想让 agent 读什么，正文本来就能直接写什么，读面不增加新说服面）；挂载（信任行为）+ 激活（正文已注入）之后二次确认是重复摩擦；收口已把可达面压回导入事实。

6. **内容纪律：文本单文件。** NUL 字节启发（首 8KB）判二进制 → 结构化错误（无多模态消费面，YAGNI）；文本 UTF-8 lossy 读入（不做 charset 协商）；单文件单调用（无多文件 / glob / 偏移续读）。字节帽 1MB，超帽**拒绝**而非截断——截断的参考文档静默误导，拒绝把「读不了整份」变成显式事实、给 agent 改道机会（大文件消费走 CLI 工具产出路径）。此帽守的是直接进模型上下文的单文件注入；CLI 信道的 8MB 输出帽守进程产出审计轨迹，两者分立。

7. **执行 = 文本中继，无新执行基质。** 技能脚本执行 = agent 经 `read_skill_file` 读出脚本文本 → 作为已注册 CLI 的内容型参数（如 `python` 的 `script`）传入 → 既有 executor 临时文件落地执行。executor、注册表、审批、工具面零改动。审批门本来就在：CLI per-call 审批卡默认渲染 argv、`file` 传值内容按需展开即见实际将执行的脚本文本全文（ADR-0109 Decision 8）；设了 `no_confirmation` 的用户已信任任意代码，技能脚本不超出该范围。挂载不在执行链上——信任链 = 导入（信文本）→ 激活（文本注入）→ CLI per-call 审批（信代码）。沙箱显式不解决：借道形态下脚本以注册 CLI 的全权限运行，信任靠审批门 + 技能来源二分（用户自撰 / 导入与 app 策展）。技能编写纪律：脚本自包含或数据经参数注入（与无技能的 CLI 用法同一模式）；`read_skill_file` 的 description 携带一句执行指路。「可执行」的判据在 CLI 审批轴上，不在文件位置——`references/` 里的脚本能中继执行，`scripts/` 里的散文只是散文。

8. **记账零变动。** 读与执行是轮内工具调用、非技能状态突变——无新 `RecipeEntry` 变体、recipe format_version v6 维持、`TurnProvenance.skills` 仍记激活集。审计走轨迹（工具调用记录）。诚实残余：附带文件跨轮可静默变化，无 `content_hash` 锚定——resume 重放不保证同内容，与 MCP 工具产出同姿态。

## Context

ADR-0110 Decision 6 把渐进披露第三层（技能目录附带 scripts / references / assets 的按需读取）整体推迟至未来信任模型 ADR，预判「沙箱 + 审批 + FS 收口下的受限可读面一并裁决」。推迟时分界在读 / 执行不对称：读取与正文同级风险类（提示注入面），挂载 + 激活闸门即够；脚本执行是任意代码执行，质变，需沙箱 + 审批——预期解锁顺序为读先行、执行待沙箱。

本 ADR 即该裁决：读面按预判落地；执行侧的「待沙箱」前提被借道消解——app 自建执行才需要沙箱，骑在已带全套纪律（CWD = 会话临时目录、per-call 审批、字节帽、轮级取消；ADR-0108/0080）的注册 CLI 信道上，执行安全模型已存在，唯一新物是使用模式。app 无通用文件工具、`fs_acl` 是 DuckDB `read_*` preflight 专用——附带文件读取需要自有的受控信道。link 导入模式下技能目录本体即外部目录的 symlink / junction，树内还可能藏外指 symlink——免审批 + agent 可指定相对路径的组合使收口成为安全核心（`fs_acl` 的防护范式——canonicalize 跟随 + 组件级前缀——已在库中且经 ADR-0088 审计）。

## Why

1. **读取与正文同级风险**：读面不新增信任面；免审批不放大可达面（收口已界定）。
2. **app 代读 + 无路径暴露**：路径一旦揭示即成通用文件读取的原材料（gemini-cli 条目携带绝对路径是既有反例）；受限元工具是唯一信道，外部运行时纵有自家文件工具也拿不到路径。
3. **发现走正文 + 错误驱动清单**：目录结构提示是免审批信道上的额外广告与注入面；正文点名 + 失败列清单已闭合发现回路（目录请求 / 查无路径都触发清单）。
4. **拒绝优于截断**（内容帽）：超帽的显式拒绝保留 agent 的改道能力；截断只留下静默误导。
5. **文本中继是最诚实的借道**：审批卡对 `file` 传值内容提供按需查看（ADR-0109 Decision 8），展开即见实际代码——任何引用形式都更弱；与 agent 自写脚本传 CLI 无异——不新增信任面，`scripts/` 无目录级特权。
6. **路径标记买不到想买的**：注册项内容型参数是文本语义，标记形式造成同参数双模混乱；CWD 仍是会话临时目录，脚本内相对路径照样断；审批键控分叉（CLI 的 always-allow 覆盖不覆盖技能脚本）难题全数复活。
7. **记账零变动是对的**：timeline 记状态突变，轮内工具调用不是；文件级 hash 锚定是无底洞（哪些文件？拒读记不记？超帽记不记？）。
8. **导入 UX 零改动**：「含脚本」标注暗示导入即信任代码——误导信任模型（导入只信文本，代码执行许可权在 CLI 审批轴上，与导入行为无关），且无任何下游消费方。

## Considered options

- **显式 path 参数的通用文件工具**：通用可达面，在 `fs_acl` 预留钩子之外另开读取信道。**否决**——读面必须是技能限定元工具。
- **`activate_skill` 返回目录结构**：免审批信道上的结构广告；gemini-cli 展示目录是既有反例。**否决**——发现走正文。
- **`scripts/` 阅读禁令**：0086 禁令禁的是执行基质不是阅读；整目录树统一文本规则更简。**否决**。
- **二进制支持**：无多模态消费面。**否决**——结构化错误。
- **超帽截断 + 诚实标记**：截断的参考文档静默误导。**否决**——拒绝。
- **路径标记形态（`skill:foo/scripts/bar.py` 经 executor 解析为真实路径）**：内容型参数双模混乱、审批面退化为名字、审批键控分叉、且买不到脚本相对访问（CWD 纪律不动）。**否决**。
- **包装元工具 `run_skill_script(name, path, cli, args)`**：绕开注册项参数表自行拼装命令行 = 新执行基质换皮；其唯一优点（独立审批面）在文本中继下不需要。**否决**。
- **导入「含脚本」分类标注**：误导信任模型、无下游消费方。**否决**——零导入 UX 改动。
- **升 format_version / 新事件变体 / 出处记附带文件**：读与执行非状态突变；轨迹已留工具调用记录。**否决**——记账零变动。

## Consequences

- **校准 ADR-0086**：「v1 不执行技能自带的 `scripts/`」读作「附带文件（含 `scripts/`，无特权区）经受限读面统一可读；执行经注册 CLI 信道文本中继——app 无专门执行面」；0086 Why 3 对「激活自带脚本需新 ADR」的预判由本 ADR 以借道形态履行（沙箱显式不解决）。
- **校准 ADR-0110**：Decision 6 推迟的第三层由本 ADR 落地——受限读面 + 执行文本中继；「沙箱 + 审批 + FS 收口」的预判形态改写为借道消解；`activate_skill` 只返回正文、不携带目录结构提示的纪律维持。
- **延伸 ADR-0105**：元工具家族新增 `read_skill_file`（激活集非空时挂载）——同一装配纪律；三件套维持 MCP 专属、直列形态不变。
- **CONTEXT.md 校准**：「技能」条目渐进披露三层完整化（元数据常驻 → 激活正文 → 附带文件按需读取）；「技能激活」条目补激活的附带文件可读后果；「网关」条目元工具枚举纳入 `read_skill_file`。
- **留实施期**：`read_skill_file` 出入参形状与 description 措辞（含执行指路句）、清单条目帽数值、1MB 帽常量落位、mid-session 注册表删除的诚实错误措辞。
