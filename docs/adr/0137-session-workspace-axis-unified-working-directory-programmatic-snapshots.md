# 会话工作区轴：统一工作目录、惰性创建默认工作区与程序化数据快照

## Decision

1. **会话头 `workspace: Option<canonical path>`，创建时定、终生不可变。** 路径存储前 canonicalize（Windows 8.3 短路径令同一目录呈现两个拼写、路径比较失配），持久化随 recipe，resume 恢复；存量会话（无字段）读作 `None`。换工作区 = 开新会话——没有会话内切换状态机。

2. **默认惰性创建时间戳工作区。** 未显式选目录的会话，在首个落盘需求时刻（外部轮 spawn、内置轮文件写入）由 App 创建 `{Documents}/TOPTOPDuck/workspaces/<时间戳>/` 并绑定为该会话工作区；纯聊天与只读查询零目录。创建的工作区若在会话关闭时仍为空则回收。

3. **内外轮 cwd 统一 = 会话工作区。** 外部轮的 `AcpTurnInput.cwd` 与内置轮的相对路径基准、scratch 落点全部取会话工作区；`temp_path` 退出工作文件域。多个会话可共享一个工作区（canonical 路径相同即视为同一个），续作与跨任务共享由「新会话选回既有工作区」表达。

4. **SQL read 放行集放开为全路径，引用即程序化快照。** preflight 从「temp root」放开为 cwd 内与绝对路径全路径；被引用文件走与手动 ingest 同一条 copy-in 快照管道（`snapshots/<ref>.duckdb` 落盘、指纹、水印、resume 免重放、stale 语义全继承）——程序化 ingest 与手动 ingest 只差触发者。共享位置大文件的快照成本与现状手动 ingest 同款（会话树内落盘，不碰用户目录与共享位置）。

5. **会话创建选择器带最近工作区列表。** 可选用户目录、选回最近工作区（App 工作区与用户目录混排、canonical 去重置顶）或默认惰性创建；最近列表存 app-config（10 个——入口截断而非数据截断，更旧的工作区由目录浏览与全量搜索兜底）。

6. **manifest 原位引用，物化产生面退役。** deliverable manifest 改为原位引用工作区内文件，不再拷贝进会话树；`assets/` 哑文件物化（SQL 引用重写）与 `artifacts/` 提及物化的**产生面**一并退役——惰性创建后 temp 永无工作文件，两域俱空。预览渲染 scope 改为**文件级白名单**（manifest 引用过的具体文件），不放行整个工作区目录。**消费面原样保留**（fs_acl 对 `assets/` 的只读放行、`isWithinArtifactsDir` 检查、按绝对路径读 manifest 与重放 SQL）——存量 recipe/manifest 记录的是绝对路径，消费面不动即存量兼容，零新增代码。

7. **归属原则：文件归工作区，状态归会话树。** 工作区（用户目录或 App 创建的目录）承载一切工作文件、中间产物与交付物，文件管理器直接可见；会话树（`recipe.json` + `analytics.duckdb` + `snapshots/`）承载纯状态，零文件副本。app 对工作区目录零自写入：快照 copy-in 是读用户文件，agent 的写入是 agent 行为经审批门，导出是用户动作。

8. **命名：目录轴用「工作区」。** 会话内数据面板让词（占位名先行，正式名后续按同类产品面板用词校准）。

## Context

外部轮 cwd 与内置轮 scratch 基准均为 `temp_path`（ADR-0012，drop 即清）：coding 类 CLI 无法围绕用户目录工作，回复未提及的产物随会话消亡；数据分析的工作脚本与中间产物无沉淀位，不可跨会话复用——实际工作流中它们是跨会话资产而非垃圾。内外轮用户约六四开的双主形态，两侧须同权受益。引擎终态（ADR-0136）已把源统一为 copy-in 文件快照（页逐出、伴生库水印、快照键与路径解耦——改名/搬树不触发重放），手动 ingest 本身就是 copy-in 快照管道，程序化引用与之只剩触发者差异。外部轮经 MCP 桥同样物化（gateway-side promotion 回流），内外轮在数据面上已同构。同类产品的通行形态：工作区是 agent 在哪个目录干活的目录（会话创建时定、不可变、可被多个会话共享），工作区内以约定文件承载项目记忆，无项目对话有默认目录（时间戳目录，可被后续任务选回，会话内不可更换）。本仓 UI 中「工作区」一词现被会话内数据面板占用（收起/展开工作区），目录轴与其同屏冲突。

## Why

1. **惰性创建而非会话创建时必选**：纯聊天零目录成本（轻问不留痕，与重活自然分流）；首个落盘需求才建，空目录垃圾不发生；空工作区回收再兜一层（同类产品的默认创建目录存在空目录堆积的实证形态）。
2. **不可变（钉死）**：同类产品五家先例一致——一个会话一个工作语境；换语境 = 开新会话，跨会话延续靠工作区及其中记忆而非会话内切换；会话头不可变消灭归属歧义，也不需要 turn-boundary 切换状态机。
3. **内外统一而非分层**：双主形态同权；外部轮的产物出口只有文件系统（无结构化捕获钩子），内置轮的工作脚本与中间产物是跨会话资产——两者都要求持久 cwd。曾据「scratch 是垃圾该即焚」分层论证内置轮留 temp，被实际工作流证伪（分析中间产物被跨会话复用）。
4. **程序化快照与手动 ingest 同管道**：指纹、水印、免重放、stale 语义全部继承，零新机制；快照冻结保住分析可复现；内存安全由引擎终态背书。一个无法区分的场景（cwd 内 agent scratch 与用户原有文件）因此只有一条通道。
5. **manifest 原位引用**：工作区已持久，拷贝进会话树冗余；原位引用 + 存在性 render-time 与既有语义一致；文件级白名单防止用户目录内任意 html 被喂进 iframe 渲染——scope 从「目录内」收紧为「manifest 点名过的文件」。
6. **时间戳工作区可被选回（1:N）**：共享与续作由「新会话选既有工作区」表达，「轻问变重活就地升级」「会话内换工作区」等概念因此不存在——默认工作区本身持久且有沉淀，重活继续在该目录里干、下次选回即可。

## Considered options

- **工作区实体账本（目录持有有序会话列表，账本为真、cwd 仅校验）**：无手动排序与按项目归档诉求，两写一致性成本（双写 + pending 标记 + 启动解析）无对应收益；「按工作区分组」始终是会话头字段的读取时派生。**否决**。
- **home 目录兜底默认 cwd**：agent 向用户主目录写文件是意外副作用，无项目对话的默认位置应是显式创建的目录。**否决**。
- **创建会话时逼选目录**：纯聊天与只读查询会话无目录需求。**否决**——惰性创建。
- **会话内 turn boundary 可换工作区**：同类产品五家先例全钉死；一个会话一个工作语境，换语境开新会话（跨会话延续由工作区与记忆承载）。**否决**——不可变。
- **conversation 态共享后备目录（所有未选目录的会话共写一个持久目录）**：scratch 与产物混灌一个目录、垃圾被「不随会话删」语义保护、堆积无解；per-session 子目录则删会话丢未另存产物。**否决**——惰性创建 per-会话工作区。
- **「conversation / 项目」双态模型**：惰性创建的时间戳目录与用户目录同为持久工作区，只是来源不同——双态表述退役为单一「工作区」概念。**否决**。
- **cwd 内引用冻结拷贝 + 物化体积护栏**：程序化快照统一管道后（copy-in 落盘 + 页逐出），护栏需求消失。**否决**。
- **保留 `assets/` 哑文件物化与 `artifacts/` 提及物化**：惰性创建后 temp 永无工作文件，两域俱空；工作区已持久，拷贝冗余。**否决**——产生面退役、manifest 原位引用，消费面保留（存量兼容）。
- **目录扫描通道（未提及交付物保底物化）**：提及物化与 SQL 引用两类已有出口，剩余一角靠模型自觉通常够。**否决**——等真实痛点。
- **目录轴命名「项目」/ 数据面板保留「工作区」词**：前者时间戳创建目录叫「项目」勉强，「工作区」与同类产品定义完全同构；后者同屏两义（选择工作区 / 收起工作区）不可接受。**否决**——目录轴用「工作区」，面板让词。

## Consequences

- **校准 ADR-0089**：`assets/` 物化域收窄至存量——新会话不再产生哑文件与 SQL 重写；存量 recipe 指向 `assets/` 绝对路径的重放照常（fs_acl 放行不撤）。
- **校准 ADR-0124**：`artifacts/` 物化产生面退役，manifest 原位引用工作区内文件；回复扫描通道按 cwd 解析的原位行为不变，temp 命中分支随域空自然失活；预览 scope 收紧为文件级白名单（`grant_artifact_asset_scope` 为挂点）。
- **校准 ADR-0080**：read 面放开绝对拼写后，路径收容（`..` 穿越与符号链接出界的解析后拒绝）对绝对拼写失效——收容仅对相对拼写（进程 CWD 解析后落界外者）存续；非对抗威胁模型与 canonicalize 解析语义不变。
- **删除语义解耦**：删会话不删工作区（文件是用户资产或跨会话共享资源）；删工作区后 manifest 引用悬空，走既有 render-time 存在性显示。
- 最近工作区列表入 app-config（选择器预填与列表，canonical 去重）。
- wire 面 `SessionMetadata` 携带 workspace 字段——侧栏按工作区分组是将来纯前端派生。
- 会话树不再有任何「替 cwd 保管文件」的职责；`temp_path` 仅在未创建工作区的纯内存轮中存在。
- CONTEXT.md 增「工作区」词条（目录轴定名，数据面板让词占位先行）。
- 非目标（另行裁决或后续票）：工作区 `AGENTS.md` 发现注入（项目记忆，暂缓执行）、手动「新建工作区」入口、快照冻结与活工作区的漂移可见性、agent 主动维护工作区记忆、项目技能挂载、侧栏分组、未提及交付物保底物化、面板正式名、消费面死代码清理（待存量会话衰减）。
